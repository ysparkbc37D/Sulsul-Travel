# 술술트래블 (Sulsul Travel)

> 현재 작업 버전: **v1.9.1** · 함께 계획하고 현장의 순간을 이어 쓰는 오프라인 우선 여행 다이어리.

술술트래블은 개인 브라우저에 여행 데이터를 저장하는 정적 웹 앱입니다. Gemini AI는 사용자가 요청할 때 계획·기록 초안을 돕고, 최종 일정과 기록은 사용자가 검토하고 저장합니다.

## 지금 할 수 있는 일

- **선택형 가상 예제**: 첫 방문은 빈 내 여행에서 시작합니다. 가상 타이베이·타이중 5일 예제를 선택해 일정·기록·출력을 살펴볼 수 있으며 설정에서 예제 초안을 삭제하면 다시 자동 등록되지 않습니다. 기존 개인 여행과 별도 사본은 유지합니다.

- **큰 계획과 상세 일정**: 여행지를 거점으로 묶고 날짜·숙소·우선순위를 편집합니다. 거점이나 선택한 날짜 범위만 AI로 다시 제안받을 수 있습니다.
- **여행 중 일정 조정**: 오늘 화면에서 다음 일정, 완료 상태, 이동 정보와 RePlan 제안을 확인합니다. 완료·고정 일정은 재생성 보호 대상으로 취급합니다.
- **여행 기록**: 같은 날 여러 순간을 글 또는 사진으로 남기고 일정에 선택 연결합니다. 하루 회고와 각 일정의 기록은 따로 보존하며, AI 다듬기는 원문과 비교·승인 후 저장합니다.
- **가계부**: 여러 통화의 지출·환전·예산을 관리하고 지출 거래와 사진을 편집합니다. 영수증 OCR은 사용자가 요청할 때 실행됩니다.
- **여행 공유와 백업**: 작은 일정 사본은 길이 제한 안에서 링크로 복사하고, 큰 데이터는 JSON 파일로 전달할 수 있습니다. GitHub Gist는 개인 백업이며 실시간 공동편집은 아닙니다.
- **여행 이야기**: 날짜별 예정/완료/건너뜀 일정, 순간·일정 글·하루 회고를 PDF·Markdown·텍스트로 출력합니다. 원문/승인문·사진을 선택하며 기록하지 않은 실제 방문 시각이나 경험을 만들지 않습니다.
- **선택형 동행 연결**: Supabase 서버를 설치하고 연결하면 보기/편집 초대, 공동 계획 확인·전송, 변경 이력과 충돌 검토를 사용합니다. 개인 글·사진·지출은 공동 서버에 보내지 않습니다. 설정 전에는 비활성입니다.
- **오프라인 사용**: 캐시된 앱과 기기 저장 데이터는 네트워크 없이 볼 수 있습니다. AI, 새 지도 타일, 환율 갱신, Gist 백업에는 네트워크가 필요합니다.

## 데이터와 개인정보

- 공개 앱에는 개인 여행 계획·확정 항공편·거래·일기를 기본 자료로 넣지 않습니다. 기존 기기에 저장된 구 예제는 개인 로컬 계획으로 보존하며, 사용자 요청 없이 지우거나 다른 사람에게 전송하지 않습니다.

- 전체 여행 데이터는 `localStorage`의 `st_trips_v2` 한 문서에 저장됩니다. 여행 사진도 현재는 이 문서에 압축된 이미지 데이터로 포함되므로 브라우저 저장 용량이 찰 수 있습니다.
- 새 기록 사진은 비율을 유지한 보관본과 썸네일을 IndexedDB에도 저장합니다. JSON 사진 보관본은 기존 백업·공유를 위해 유지하므로 저장 용량 한도는 남습니다. 저장 실패 시 순간·하루 사진 초안을 유지하고 재시도·파일 보관을 제공합니다.
- `st_gemini_key`와 `st_github_pat`은 브라우저 저장소에 암호화되지 않은 상태로 보관됩니다. 공유 기기에서는 사용하지 마세요.
- AI 실행 시 요청에 필요한 여행 설명, 일정·일기 텍스트 또는 사용자가 선택한 영수증 이미지가 Google Gemini API로 전송됩니다. Gist 백업은 전체 여행 데이터를 GitHub로 보냅니다. 공유 파일과 링크에는 선택한 기록·금융 정보를 넣을 수 있습니다.
- Gist 복원은 현재 기기의 여행 목록 전체를 백업 내용으로 교체합니다. 복원 전에 현재 데이터를 별도 백업하세요.

## 사용 전 확인할 제한

- 동행 서버는 기본 미설정입니다. [설치 안내](docs/collaboration-setup.md)와 SQL/RLS 실제 검증을 마친 뒤 활성화하세요. 서버 변경은 확인/전송 버튼을 통해 반영하며 자동 실시간 병합은 하지 않습니다. 현재 임시 로그인은 기기 간 같은 계정의 복구를 제공하지 않습니다.
- 사진 보존 용량 확대를 위한 완전한 IndexedDB 미디어 저장소와 자동 이전은 후속 과제입니다. 기기 변경·브라우저 데이터 삭제 전에 JSON 백업을 만드세요.

## 구조

```text
index.html                         앱 셸, 화면, 기존 화면 로직
js/domain/                         여행 사본 계약, RePlan 도메인
js/application/                    AI 작업 오케스트레이션
js/infrastructure/storage/         여행 저장소, 일기 초과 저장소
js/presentation/                    동행 화면, 기록 편집, 지출 편집, 공유 UI
js/destinations/                    기본·남미·원난 목적지 지식 팩
kb-travel.js                       예시 여행·초기 여행 템플릿
sw.js                              앱 셸 오프라인 캐시
css/                               앱 스타일 및 로컬 유틸리티 CSS
tests/                             계약·브라우저 통합 검사
```

앱은 Vanilla JavaScript 기반 정적 PWA이고 개인 사용은 서버에 의존하지 않습니다. 입력 계약·사진·날짜별 이야기·선택 협업 모듈을 기존 앱 셸에 연결했습니다. [v1.8.9 구현 기록](docs/implementation-v1.8.9.md)과 [모바일 검토 보고서](docs/ux-review-v1.8.8-2026-10-07.md)를 참고하세요.

## 로컬 실행과 검증

PowerShell에서 저장소 루트의 `.\tools-serve.ps1`을 실행하고 `http://localhost:8080/`을 엽니다. PWA와 서비스워커 검증에는 `file://` 대신 localhost를 사용합니다.

Node.js 18 이상이 있는 환경에서는 다음을 실행합니다.

```powershell
node --test tests/*.test.mjs
node tests/activity-journal.browser.cjs
node tests/expense-editor.browser.cjs
node tests/reliability.browser.cjs
node tests/mobile-ui.browser.cjs
node tests/moment-journal.browser.cjs
node tests/travel-story.browser.cjs
node tests/companion-refresh.browser.cjs
node tests/collaboration-review.browser.cjs
.\tools-verify.ps1
```

브라우저 검사에는 Playwright와 Chromium이 필요하며 실제 Gemini 키를 호출하지 않고 합성 여행 데이터로 실행합니다. 실기기 카메라·키보드·메신저 링크 인식은 별도로 확인해야 합니다.

## 배포와 버전

운영 앱은 저장소에 연결된 Vercel 프로젝트가 `main` 브랜치의 변경을 배포하며 주소는 [sulsul-travel.vercel.app](https://sulsul-travel.vercel.app/)입니다. `vercel.json`은 `node tools/build-public.cjs`로 생성한 `public`만 제공하도록 지정합니다. Node 기본 모듈로 공개 앱 파일만 복사하며 런타임 의존성을 추가하지 않습니다. 개발 문서·첨부·검사·참고 이미지는 배포 산출물에서 제외합니다. 기존 산출물이 있으면 임의 삭제·덮어쓰기 없이 빌드를 중단하므로 로컬 재검증은 `.local-review`의 새 출력 경로를 사용하세요. GitHub Pages는 호스팅 대상이 아닙니다. 새 버전에서는 `index.html`·`sw.js`·`package.json`·변경 기록을 함께 갱신합니다. 공개 자료 수정은 [v1.9.0 개인정보 경계 기록](docs/privacy-demo-v1.9.0.md), 기존 기기의 초안 정리는 [v1.9.1 후속 기록](docs/privacy-existing-v1.9.1.md)을 참고하세요.
