# v1.9.7 여행 중 자유 편집 구현

2026-11-02 · 기준 v1.9.6(`fd827a0`). [수정 전 검토](live-itinerary-review-2026-11-02.md)의 시간 범위 오해석, 중간 삽입과 다른 날짜 자동 정렬을 우선 수정했다. 개인 여행을 공용 예제로 사용하지 않았다.

## 사용 흐름

- 오늘·큰 계획 상세의 카드 사이 **여기에 추가**, 또는 **순서·위치 편집**을 켜서 카드 앞/뒤에 추가한다. 제목만 넣고 시각은 비워 둘 수 있다.
- 순서 편집 모드에서 위/아래 이동, 날짜·위치 선택 이동, 나중에 갈 곳, 일정에서 제거를 선택한다. 순서를 바꿔도 시각은 자동으로 바꾸지 않는다.
- 일반 추가 폼에서는 시각에 맞춰 삽입/맨 앞/맨 뒤/선택 항목 앞·뒤를 고른다. 시각 기준도 새 항목 위치만 계산하고 기존 순서를 전체 정렬하지 않는다.
- 제거·보류·취소 항목은 보관 목록에서 복구한다. 영구 삭제 대신 상태를 보관하므로 글·사진과 연결 ID가 유지된다.
- **변경 되돌리기**는 최근 수동 변경을 되돌린다. 입력·내용 수정, 날짜·순서 이동, 대체와 지연 묶음도 이력에 남긴다. 대상의 계획이나 순서가 이후 변경되면 안전하게 거절한다.
- **변경 이력·기준 계획**에서 최근 30개 명령과 첫 편집 직전 보관한 기준안을 본다. 기존 여행의 출발 전 원본이라고 표시하지 않는다.

기존의 완료 방문·기록은 별도 접기 영역에 유지한다. 완료 항목을 제거·보류·대체하려면 먼저 완료를 취소한다. 수동 편집은 AI나 네트워크 없이 가능하다. 스와이프/드래그가 없어도 버튼과 위치 선택으로 모든 이동을 수행할 수 있다.

## 코드와 저장 경계

| 파일 | 역할 |
| --- | --- |
| `js/domain/live-itinerary.js` | 공통 시간 해석, 안정 ID 명령, 기준안·최근 이력·최소 역명령 Undo |
| `js/presentation/live-itinerary-ui.js` | 삽입·순서·날짜 이동·보류·복구·이력 UI |
| `js/presentation/live-itinerary-bridge.js` | 기존 폼을 같은 command 경계로 연결하고 저장 성공 뒤 화면 채택 |
| `css/live-itinerary.css` | 편집 모드·이동·이력 화면의 모바일 배치 |

`trip.days` 배열을 현재 계획의 호환 원본으로 유지한다. 사용자가 정한 배열 순서와 시각을 분리하고 편집 범위 밖 날짜를 정렬하지 않는다. 새 저장소로 대량 이전하지 않는다.

명령은 `insert/update/move/remove/defer/restore/replace/batch/undo`다. 출발/도착 날짜 ID, 항목 ID, 삽입 기준 ID와 앞·뒤 위치, 여행 ID와 기대 revision으로 범위를 검사한다. 날짜 이동은 동일 ID와 원래 장소 도시를 유지한다. 기록 객체·사진·원문·recordId는 편집 명령으로 덮어쓸 수 없다.

기준 계획 `planBaseline`은 첫 수동 명령 직전에 계획 필드만 보관한다. `source:captured-current`로 현재 상태 채택임을 표시한다. `planHistory`는 사진을 매번 복제하지 않고 바뀐 계획 필드·위치·지문만 최근 30개 보관한다. Undo는 해당 계획이 이후 바뀌지 않았는지 확인하면서 나중에 추가된 글·사진 연결을 보존한다. 삽입 Undo도 항목을 보관 상태로 전환하여 기록을 보호한다.

전체 백업은 기준안·이력을 보존하며 가져오기 전에 역패치 필드·위치·ID와 메타데이터 형식을 검사한다. 이미 기기에 남은 손상 이력은 화면을 멈추거나 임의 초기화하지 않고 안내하며, 해당 이력으로 변경하지 않는다. 저장·복원에서 보충하는 기본 분류는 후속 계획 변경으로 오인하지 않는다. 기본 사본·공동 계획 공유에는 현재 계획을 보내고 로컬 기준안·Undo 이력을 자동 공개하지 않는다. 공동 계획의 기존 보기 전용 보호와 전체 JSON 충돌 검사를 유지한다. `planRevision` 추가만으로 원자적 다중 기기 병합을 보장하지 않는다.

시간 범위와 `+N일`은 같은 시작 시각 해석을 사용한다. 시각 미정은 지연 계산에서 임의 시각으로 채우지 않는다. AI 보호 검사도 제거·보류 항목을 되살리지 않도록 확장하고 RePlan이 저장 배열을 자동 정렬하지 않게 했다. 실제 교통·예약 API를 새로 연결한 것은 아니다.

화면 갱신은 오늘·큰 계획·열린 상세와 필요한 지도/가이드에 반영하고 스크롤을 복원한다. 숨겨진 전체 30분 시간표는 매번 다시 만들지 않고 해당 화면을 열 때 갱신한다. 지도 거점 가이드는 실제 길찾기/교통 소요 엔진을 대신하지 않는다.

## 재현과 검증

초기 통합 검사에서 위치 입력란이 늘면서 모바일 스팟 저장 버튼이 뷰포트 밖으로 밀리는 문제를 발견했다. 버튼 클릭을 강제하지 않고, 기존 header/body/footer 스크롤 레이아웃을 적용해 입력 영역만 스크롤되고 저장 영역이 보이도록 수정했다. 320px에서 다음 방문의 주 행동이 가려지지 않도록 오늘의 편집 도구는 다음 일정 카드 아래에 배치한다.

- 시간 해석과 범위 불변의 단위 검사, 명령·Undo·기록 보존·도시 이동의 도메인 검사.
- 45일 합성 여행에서 320/390px 실제 클릭으로 앞/뒤 삽입, 시간 미정 추가, 순서 이동, 다른 날 이동, 제거/Undo, 보류/복구를 연속 수행한다. DOM 순서와 저장 문서, 다른 날짜, 완료, 원문·승인문·AI 초안·사진을 대조한다.
- 모든 명령의 용량 실패/재시도, 실제 폼 입력과 이동 위치 선택 보존, 두 탭 충돌·여행 변경·잘못된 ID 범위, 기록 추가 뒤 계획만 Undo를 확인한다.
- 실제 서비스워커의 오프라인 새 페이지 재진입과 오프라인 편집, 구 워커 업그레이드·기존 기록 저장·AI/백업/출력 회귀를 확인한다.
- 최종 단위 검사 188건을 통과했다. 손상 이력의 조회·명령·복원 거절과 정상 전체 백업 왕복 뒤 Undo도 포함한다.

브라우저 검사는 합성 자료만 쓰는 Edge Chromium이다. 물리 휴대폰·iOS 기기나 실제 동행 서버 두 계정 검증을 대신하지 않는다. 선택 항목만 대상으로 하는 AI patch 오케스트레이션, 실제 시간/예약 충돌 조회, IndexedDB 항목별 원본 이전과 동행의 항목별 자동 병합은 후속 범위다. 이번 배포의 핵심은 직접 현장 편집과 계획/기록 보존 경계다.
