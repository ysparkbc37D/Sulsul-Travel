# v1.8.0 일정별 사진·에세이 기록

2026-09-14. v1.7.9 다음 버전은 저장소의 순차 올림 규칙에 따라 v1.8.0이다.

## 사용 흐름

1. 전체 시간표, 큰 계획 상세 또는 오늘 화면에서 **사진 · 짧은 글 남기기**를 누른다. 완료 전·후 모두 가능하고 기록 저장은 일정의 완료 상태를 바꾸지 않는다.
2. 글만 또는 사진만 저장할 수 있다. 일정당 사진 최대 8장, 한 파일 20MB 이하. 사진은 중앙 크롭한 336×448 JPEG로 압축한다. 카드에는 대표사진 한 장만 60×80px로 표시하며 두 줄을 넘는 글은 접는다.
3. 기록창에서는 사진을 눌러 크게 보고 대표사진을 선택한다. 사진 삭제는 확인 후 초안에서 제외되며 저장하면 반영된다.
4. **AI로 다듬기**는 원문을 먼저 저장하고 기존 Gemini/오케스트레이터를 호출한다. 원문과 제안을 비교해 승인해야 반영된다. 원문을 보존하며 생성 후 기록을 수정했거나 여행 revision이 바뀌면 적용하지 않는다. 사진 분석은 요청하지 않는다.
5. 저장 실패 시 창과 초안을 유지하고 재시도·글 파일 보관을 제공한다. 사진 압축 중 저장은 막으며, 다른 날짜를 보더라도 처음 열었던 일정에 저장한다. 닫기와 뒤로가기는 미저장 변경을 확인한다.
6. 기록 탭의 **일정마다 남긴 순간**, 기록 통계, PDF/HTML 보고서에서도 확인한다. 일정이 삭제·재생성되어 연결이 없어져도 당시 제목·시간·도시와 기록은 보존된다.

## 저장 및 AI 경계

- 새 모듈: `js/presentation/activity-journal.js`. 기존 일별 `trip.journals` 형식은 유지하며 대규모 데이터 이전은 없다.
- `trip.activityRecords[recordId]`: `id`, `text`, `photos`, `coverIndex`, `context`(title/date/time/city), `updatedAt`. AI 승인 시 `originalText`, `aiDraftAcceptedAt` 추가.
- `spot.recordId`는 저장 성공 때만 생성·연결한다. 배열 인덱스를 영구 식별자로 쓰지 않으며, 일정 정렬·날짜 이동 시 연결이 따라간다. 첫 저장 전에 일정이 변경되어 유일한 대상을 찾지 못하면 적용을 중단한다.
- 수동 저장은 복사→검사→repository 저장→State 반영 순서. 기존 기록이 바뀐 경우 수동 저장도 충돌로 처리한다. AI는 별도 `activity-journal` 작업 종류와 기존 승인/재시도 상태 머신을 사용한다.
- 공유 시 기록·사진 체크박스를 선택해야 `activityRecords`가 포함된다. 전체 JSON/Gist 백업은 보존하며, 가져오기 시 형식·대표사진 범위·사진 URL을 검증한다.
- 서비스 워커에 새 모듈을 사전 캐시한다. 기록의 로컬 조회·편집에는 네트워크가 필요하지 않고 AI 호출에만 필요하다.

## 검증

`node --test tests/*.test.mjs`, `node tests/activity-journal.browser.cjs`, `node tests/reliability.browser.cjs`, `node tests/mobile-ui.browser.cjs`, `./tools-verify.ps1`.

최종 결과: Node 50개 통과/0개 실패, 일정 기록·공유/저장 안정성·기존 모바일 브라우저 검사 통과, 새 모듈을 포함한 오프라인 캐시/재시작 검사 통과, 종합 게이트 5개 통과. 첫 종합 실행에서 기존 CDP 판독의 빈 응답 오류가 발생했으며 재실행에서 정상 통과했다. AI 승인 저장 실패 후 검토창 유지/재시도, 사진 처리 중 날짜 이동과 브라우저 뒤로가기 취소도 확인했다.

새 브라우저 검사는 사용자 프로필과 분리된 합성 여행 및 고정 AI 응답을 사용한다. 완료 전 저장, 실제 Canvas 압축, 대표사진 변경·확대, 저장 실패·재시도, AI 승인·원문 보존·미저장 수정 충돌·연결 실패, 닫기/뒤로가기 방어, 320~430px 카드 경계와 520px 높이의 푸터, 일정 이동·삭제 후 보존, 공유 선택과 PDF/재시작을 검사한다. 실제 API 키를 사용하거나 여행 데이터를 서버로 보내지 않는다.

## 범위와 한계

- 한 일정에는 편집 가능한 기록 한 편이며, 하루 일기는 기존 한 편 구조다. 같은 날 여러 일정의 기록은 각각 따로 남는다.
- 사진 압축본만 보관하며 원본 보존 기능은 아니다. 사진 원본 파일은 사용자 기기에 유지한다.
- 미저장 초안은 현재 창의 메모리에 있으므로 앱 종료 전 저장해야 한다. 용량 초과 시 새 일정 기록에는 아직 IndexedDB 보조 저장을 적용하지 않으며 실패를 알리고 재시도/TXT 보관을 제공한다.
- AI가 일정을 교체하면서 연결 ID를 없앤 경우 해당 기록은 기록 탭에 보관되며 다른 일정에 추측해서 연결하지 않는다.
- 실시간 공동편집, 하루 자유 기록 여러 편, 전체 여행 AI 에세이는 후속이다. 모바일 에뮬레이션 통과는 실제 Android/iOS 사진 선택창과 키보드 검증을 대체하지 않는다.
