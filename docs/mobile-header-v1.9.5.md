# v1.9.5 모바일 헤더와 여행 목록 검토

2026-10-12, 기준 버전 v1.9.4. 사용자 첨부에서 상단 버전 미표시와 검색 글자 잘림을 확인하고 독립 가상 여행으로 재현했다. 개인 여행·사진·키는 테스트나 공개 예제로 사용하지 않는다.

## 원인과 적용

| 재현 | 원인 | 변경 |
| --- | --- | --- |
| 320·360·390·430px 모두 버전이 보이지 않음 | `companion-refresh.css` 모바일 규칙이 배지와 통계를 `display:none!important`로 숨김 | 브랜드 아래에 버전·통계를 배치하고 실제 클릭 가능 영역 확보 |
| 320px 검색창 폭 64px | 검색·정렬·초기화·보기 버튼이 한 줄에서 폭을 나눔 | 검색은 전체 폭, 나머지는 별도 도구 모음 |
| 필터와 긴 안내가 첫 여행을 아래로 밀어냄 | 세 상세 필터와 이전 초안 설명이 항상 펼쳐짐 | 상세 필터·설명 접기, 필터 개수와 해제 칩, 초안 관리 진입 유지 |
| 320px 카드 삭제 버튼이 잘림 | 예산과 네 개의 액션이 줄바꿈 없이 같은 줄을 사용 | 좁은 화면 하단 줄바꿈, 목록·격자 버튼 최소 44px 확보 |
| 스크롤 시 상단이 사라지고 넓은 화면 고정 메뉴의 위치도 어긋남 | body의 가로 overflow 숨김이 sticky를 막고 메뉴 위치는 72px로 고정 | 지원 브라우저에서 overflow clip으로 가로 넘침을 막고 실제 헤더 높이를 관찰해 메뉴 위치에 반영 |
| 첫 설치에도 업데이트 안내가 표시됨 | 첫 서비스워커 제어와 기존 워커 교체를 구분하지 않음 | 이전 controller가 있던 교체만 업데이트 안내 |

버전 버튼은 변경 이력을 열고, 통계·설정·추가·내 여행 기능을 유지한다. 여행 제목은 키보드로 열 수 있다. 여행 상태 선택에는 `aria-pressed`, 검색과 아이콘 버튼에는 접근성 이름을 제공한다. 큰 계획 상세는 독립 헤더의 뒤로·편집·설정을 유지하며 닫은 후 공통 헤더로 돌아간다.

## 검증 범위

`tests/header-hub.browser.cjs`는 320·360·390·430px 허브·여행 화면의 실제 버튼 노출·클릭·경계, 목록·격자 카드의 버튼 잘림, 긴 가상 제목, 큰 계획 상세의 복귀, 검색 결과·상세 필터·해제·상태 선택·키보드 여행 열기와 세 테마를 검사한다. 768·1280px에서는 스크롤 후 헤더·주요 메뉴의 겹침을 검사한다. 개인 자료를 이용하지 않는 Edge Chromium 검사이며 실제 iOS 기기 검증을 대신하지 않는다.

기존 모바일·테마·예제 시작·개인 데이터 보존 검사와 실제 구 워커 업그레이드를 함께 확인한다. 최신 버전과 SRI·프리캐시·공개 파일 빌드를 동기화한다. 신규 방문은 빈 목록과 선택형 가상 예제를 유지하고 이전 개인 초안을 자동 교체하지 않는다.

2026-10-12 최종 v1.9.5 로컬 검증 결과:

- 단위·정적 검사 162건 통과.
- 헤더·허브 브라우저 검사 35건 통과. 4개 모바일 폭과 2개 데스크톱 폭, 긴 제목·큰 예산의 가상 여행으로 확인했다.
- 서비스워커 업그레이드·첫 설치 검사 49개 검증 통과. 미저장 기록 보존과 구 캐시 복구를 유지했다.
- 여행 화면 회귀 16건, 예제 시작·개인 데이터 보존 14건 통과.
- 배포 게이트의 버전 동기화·필수 ID·모바일 필터·사진 비율·실행 오류 검사 통과. 실제 렌더링한 대상의 세 테마 글자 대비는 4.5 이상이었다. 화면 전체의 접근성을 보증하는 결과는 아니다.

이번 변경은 헤더와 여행 목록 개선이다. 하루 회고·일정 기록·순간 기록 저장소 통합, 사진 전체 IndexedDB 이전, 실제 서버 공동편집 검증은 기존 후속 과제로 남아 있다.
