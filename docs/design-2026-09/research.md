# 설계 근거 — 참고 여행과 유사 서비스

조사일: 2026-09-08. 공개 서비스 공식 제품 페이지의 기능 설명과 이미지, 로컬 앱 소스 및 브라우저 화면, 사용자 제공 Google Sheets의 메타데이터·선별 범위를 확인했다. 경쟁 앱의 유료 계정 내부 기능을 실사용 비교하거나 이동 최적성을 검증한 조사는 아니다. 아래 ‘적용’은 조사로부터 도출한 설계 판단이다.

## 1. 실제 계획표에서 발견한 사용자 행동

세 파일은 Google Sheets를 가리키는 `.gsheet` 바로가기다. 해당 원본의 14개 탭에서 헤더·초반 행을 읽고, 대만의 오른쪽 일정·윈난의 후반 일정을 추가 확인했다. 전체 셀·삽입 이미지·바우처 첨부를 전수 분석하지 않았다. 개인정보·예약 식별자·개인별 결제내역은 설계 자료에 재수록하지 않는다.

| 자료 / 읽은 범위 | 확인한 계획 방식 | 제품 요구로 변환 |
| --- | --- | --- |
| 세부 `일정정보!A1:L35`, `시트2!A1:L35`, `시트3!A1:L35` | 날짜를 가로, 시간을 세로로 배치. 공항 이동·북부 리조트·시내 숙박·식사·휴식 연결. 가족 객실 구성, 사전 밴 예약, 활동별 조건을 별도 정리 | ‘리조트 머물기’처럼 여러 날을 묶는 거점 카드. 인원·짐·휴식 요구를 이동 제약에 반영. 예약 과제와 활동 후보 분리 |
| 대만 `여행계획표_v01!A1:L35`, `M1:AA45`; 교통·숙소·경비·준비·쇼핑·old 탭의 `A1:L35` | 항공·여러 숙소·차량 대여·도보 연결·관람 마감·담당자·공금까지 연결. 이전 계획과 새 계획이 함께 존재 | 고정 예약과 유연한 관광 분리. 담당자 지정, 공금·개인 지출 구분, 변경 전후 비교. 날짜별 일정과 이동 구간을 같이 보기 |
| 윈난 `여행 계획!A1:L35`, `B35:I62`; `핵심 관광 정보!A1:L35`, `B35:B70`; `맛집!A1:L35` | 여러 도시의 숙박·철도·현지 버스·짐 보관·환승 여유시간·예약 메모·주의사항 연결. 일자별 격자와 별도 요약표 병존 | 도시 간 연결을 독립 엔터티로 관리. 이동시간 외 접근·대기·짐·환승 버퍼 포함. 서로 다른 계획안의 출처·버전 보존 |

세부 `시트4`의 초기 범위는 신원·예약 관련 정보여서 제품 요구 추출 후 추가 탐색을 중단했다. 이런 자료를 앱으로 가져올 때도 일반 여행 계획과 개인 보관함을 먼저 분리해야 한다.

### 가져오기에서 반드시 드러낼 불일치

- 대만 제목·항공 구간은 4월 9~12일인데, 숙소 표에는 4월 19~22일 범위가 남아 있다. 날짜를 자동 보정하지 말고 셀 출처를 나란히 보여준다.
- 대만 경비표에는 다른 지역 여행 제목과 여러 통화 라벨이 섞여 있다. 목적지나 통화를 표의 제목 하나로 추정하지 않는다.
- 대만 체크리스트 오른쪽에는 윈난 도시 간 이동 메모가 있다. ‘다른 여행 자료로 보임’ 후보로 분리하되 삭제·이동은 사용자가 결정한다.
- 대만 일정 본문과 우측 동선 제안의 방문 순서가 다르다. 동일 일정으로 합치지 않고 대안 버전으로 보존한다.
- 윈난 날짜별 표와 하단 요약표는 일부 이동 시각·경유지가 다르다. ‘최신’ 버전을 임의로 결정하지 않는다.
- 원본 스프레드시트의 시간대 설정도 여행지와 다르다. 세부는 Asia/Tokyo, 대만은 America/Los_Angeles, 윈난은 Asia/Seoul로 반환되었다. **문서 설정과 여행지 현지 시간대를 혼동하지 않는다.**

원본의 영업시간·운임·비자·의학적 메모는 역사적 참고다. 현행 사실로 재사용하지 않는다. 이 문서는 현재 여행 정보나 의료·입국 조언을 제공하지 않는다. 서비스에서는 적합한 공식 출처를 다시 확인하고 사용자에게 조회 시각과 적용 날짜를 보여준다.

## 2. 참고 앱 6개

| 서비스 / 관찰 근거 | 참고할 패턴 | 술술트래블 적용 판단 |
| --- | --- | --- |
| [Wanderlog](https://wanderlog.com/) — 일정과 지도, 이동시간, 공동편집, 예약, 경비 분담 | 일정과 경로를 함께 조작하는 계획 작업면 | PC는 거점 카드+경로, 모바일은 목록/지도 전환. 큰 계획을 먼저 만든 뒤 세부 시간표로 내려감 |
| [Mindtrip](https://mindtrip.ai/) — 맞춤 추천, 그룹 채팅, 의견·좋아요, 자료에서 계획 시작 | 동행자의 의견을 실제 여행 항목에 연결 | 카드마다 제안/의견. AI 대화 결과는 실행 가능한 변경안으로 변환. 채팅이 공동 계획의 유일한 저장 장소가 되지 않게 함 |
| [TripIt](https://www.tripit.com/web) — 예약 통합, 항공 알림, 여행 리마인더 | 예약과 다음 행동을 가까이 둠 | 시간 고정·예약 확인·발권 대기·확인 필요를 분리. 다음 출발과 문서 접근을 오늘 화면에 연결 |
| [Polarsteps](https://www.polarsteps.com/) — 계획·추적·회고, 사진/이야기, 여행 책·영상, 공개 범위 | 여행의 흐름이 누적 기록과 결과물로 이어짐 | 계획 카드가 실제 경험의 장이 됨. 계획에서 방문을 추론하지 않고 확인된 기록으로 여행장·에세이를 만듦 |
| [FindPenguins](https://findpenguins.com/) — 경로 추적, 사진·이야기·친구 댓글을 담는 여행 책 | 짧은 기록의 누적과 여행 후 재구성 | 순간 한 줄을 빠르게 저장하고 하루·여행 단위로 편집. 위치 수집은 선택 기능 |
| [Roadtrippers](https://roadtrippers.com/) — 경로상의 장소 발견과 로드트립 계획 | 선으로 이어진 이동과 경유지 중심 탐색 | 다도시 여정에서 거점 간 연결을 카드 사이에 표시. 도로 여행 패턴을 철도·항공까지 동일 적용하지 않음 |

경쟁 앱 전체를 복제하지 않는다. 술술트래블의 설계 가설은 **공동 큰 계획 → 제약을 지키는 현장 재계획 → 사실로 확정한 공동·개인 기록 → 평생 회고**의 연속성이 핵심 가치라는 것이다. 시장 우위나 ‘최고 UX’가 입증됐다는 뜻은 아니며 사용자 과업 검증이 필요하다.

## 3. 현재 앱에서 보이는 문제

2026-09-08 소스와 캐시가 없는 localhost 포트에서 v1.2.9를 확인했다. 기존 포트에서는 v1.2.4 캐시가 먼저 표시되어 별도 포트로 비교했다.

| 관찰 위치 | 관찰 | 개선 |
| --- | --- | --- |
| `nav-tab-*`, `plan-subtabs-nav` | 5개 주 메뉴 + 4개 일정 하위 메뉴 + 상단 통계·지도·공유 + 튜닝·추가 | 주 메뉴 4개, 오늘의 대표 행동 1개, 자세한 정보는 해당 카드 안 |
| `gps-radar-card` | 예정 여행에서도 모의 GPS와 주변 스팟이 본 일정보다 먼저 보임 | 실제 위치 허용 시에만 보조 기능. 개발용 모의 위치는 사용자 화면에서 분리 |
| `modal-install-guide` | 계획을 여는 과정에서 큰 설치 안내가 화면을 가림 | 첫 기록 저장 이후 비차단 설치 제안. ‘영구 보호’ 같은 보장 문구 제거 |
| `renderActiveTripWorkspace` | 미래 여행에서도 헤더가 ‘여행 다이어리 기록 중’으로 표시되는 화면 관찰 | 단계·실제 상태에 맞춰 안내. 날짜 경과만으로 방문/완료를 확정하지 않음 |
| `days-accordion-container` | 도시의 큰 구조를 보기 전에 긴 일자 목록과 상세 기능이 먼저 나옴 | 거점·숙박·핵심 경험을 묶은 큰 계획부터 탐색 |
| `executeScheduleTuning` | AI 실패/오프라인 fallback은 `trip.days`를 직접 교체. AI 성공은 기존 itinerary 병합 경로 사용 | 실패도 검토 상태 유지. 수정·삭제를 포함하는 RePlan Patch를 별도 적용 |
| 튜닝 프롬프트 | 대상 이유·지연분 위주이고 원본 전체 일정/고정 예약의 구조화 사본이 없음 | 입력 스냅샷과 항목 revision, 변경 범위를 고정 |
| `syncToGist` / `syncFromGist` | 전체 스냅샷 백업·복원 | 실시간 다중 사용자 작업에는 멤버십·권한·서버 버전·작업 로그 필요 |
| `sw.js` | 활성화 시 현재 이름 외 캐시를 모두 지우는 루프 | 이후 이전 단계에서 술술트래블 소유 접두사만 정리하도록 별도 검증 |

이번 범위에서는 기존 `index.html`의 미커밋 수정을 보존했다. 관찰된 구현 문제는 개발 순서에 반영했으며 수정 완료로 표시하지 않는다.
