# 모바일 여행 노트 개편 · v1.3.8

2026-09-11. 휴대폰에서 큰 계획, 하루 일정, 실제 기록을 쉽게 오가는 방향으로 기존 금색·다중 대시보드 구성을 개편했다.

## 조사와 판단

로그인이 필요한 경쟁 서비스 내부를 이용하거나 실시간 협업을 재현한 것은 아니다. 아래 공식 제품·도움말에 공개된 흐름을 비교했다.

| 참고 서비스 | 확인한 흐름 | 술술트래블에 반영한 판단 |
| --- | --- | --- |
| [Wanderlog](https://wanderlog.com/pages/help-center) | 일정과 지도 연결, 공동 편집, 예약·비용 정리 | 거점별 여정·전체 시간표·지도 전환을 눈에 보이게 배치하고, 전체 목록 중복 노출을 제거 |
| [Polarsteps](https://support.polarsteps.com/hc/en-us/articles/24265886208914-How-do-I-plan-my-trip) | 계획 단계에 체류 날짜·메모를 정하고 실제 방문 후 기록으로 연결 | 거점 → 날짜 → 일정 → 방문 완료 → 기록의 단계 구분 |
| [TripIt](https://www.tripit.com/en-uk/web/how-it-works) | 예약을 하나의 여행 일정으로 정리 | 작은 기능 아이콘을 나열하기보다 현재 일정과 다음 행동을 먼저 표시 |
| [TripIt 오프라인 안내](https://help.tripit.com/en/support/solutions/articles/103000063436-using-mobile-apps-without-connectivity) | 연결이 없어도 이미 저장된 여행 정보 열람 | 외부 CDN 없이 핵심 화면이 표시되도록 CSS와 기존 아이콘·지도 엔진·공유 라이브러리를 로컬 파일로 제공 |

## 확인된 문제

- 큰 계획 아래 전체 시간표가 연속으로 반복되어 스크롤 길이가 늘어남.
- 모바일에서 10~12px 설명과 네 열로 나뉜 일정 카드 때문에 긴 도시·장소명이 밀림.
- 상단 두 곳에 기능 아이콘이 집중되고 주요 탭은 화면 위로 사라짐.
- 첫 진입 700ms 후 설치 안내가 자동으로 떠 사용자의 계획 작업을 가림.
- Tailwind Play CDN 요청 실패 시 숨김·레이아웃 유틸리티가 사라져 여러 화면이 한꺼번에 노출됨.
- 넓은 `bg-amber-` 문자열 선택자가 본문의 텍스트 선택 색상 클래스까지 잡아 페이지를 노랗게 만듦.

## 구현

1. 차분한 회녹색 배경, 흰 카드, 초록색 주요 행동으로 색상과 위계를 정리. 어두운 테마도 동일한 명도 위계 사용.
2. 모바일 하단에 큰 계획·오늘·기록·준비를 고정. 기기 안전 영역만큼 여백 확보. 상세에서는 전용 뒤로가기와 편집·설정 유지.
3. 큰 계획은 도시별 순서·체류 날짜·진행 상태·요약을 보여주는 목록. 카드 열기와 편집·AI 재생성을 별도 버튼으로 구분.
4. 상세에는 가로 날짜 선택기를 제공하고 선택한 하루만 표시. 제목 17px, 설명 14px, 완료·편집 버튼 44px 이상. 완료 일정은 접어서 보기.
5. 오늘 화면도 날짜 선택 가능. 완료 처리 후 사용자가 고른 날짜를 유지하며 다음 미완료 일정과 기록 버튼을 강조.
6. 기록의 사진 추가·AI로 다듬기·저장 문구 단순화, 준비 항목 확대, 모바일 사진 삭제 버튼을 hover 없이 노출.
7. 설치 안내는 배너나 설정에서 선택해 열도록 변경. 키보드로 보이는 영역이 줄면 시트를 visualViewport 안에 배치.
8. 기본 유틸리티 CSS는 사전 빌드하고 기존 외부 라이브러리는 고정 버전과 라이선스를 포함해 `vendor/`에 제공. 서비스워커 사전 캐시에도 등록.

## 코드와 검증

- `js/presentation/companion-ui.js`: 표시 계층. 기존 저장·AI 승인·편집 함수를 사용하며 별도 저장 형식을 도입하지 않음.
- `css/companion.css`: 테마와 모바일 구성요소.
- `css/utilities.css`: `pnpm build:css`로 생성한 정적 CSS. 새 Tailwind 클래스를 추가하면 재생성 필요.
- `tools/build-assets.cjs`: 고정 버전 패키지에서 배포용 라이브러리와 라이선스 복사.
- `tests/mobile-ui.browser.cjs`: 외부 요청을 차단한 독립 브라우저와 가짜 여행으로 320·360·390·430·768·1280px 검증. 도시별 그룹, 전체 시간표 분리, 날짜 선택, 선택일 추가·완료, 뒤로가기, 기록·준비 이동을 확인.

실제 Gemini 응답 품질이나 동행자 실시간 동기화는 이번 UI 검증 범위에 포함하지 않는다. 지도 타일·AI·온라인 백업은 여전히 연결이 필요하다. 데스크톱 브라우저의 모바일 뷰포트 검증이며, Android/iOS 실기기 키보드·제스처 점검은 후속 확인 대상이다.

## 개발 명령

```sh
pnpm install --frozen-lockfile
pnpm build:assets
pnpm build:css
pnpm test
```

브라우저 테스트는 Playwright를 사용할 수 있는 환경에서 실행한다. 환경에 설치된 모듈을 쓰려면 `PLAYWRIGHT_MODULE`에 모듈 경로, `CHROME_PATH`에 브라우저 실행 파일 경로를 지정하고 `node tests/mobile-ui.browser.cjs`를 실행한다. 테스트 이미지는 Git에서 제외한 `.local-review/`에 저장된다.
