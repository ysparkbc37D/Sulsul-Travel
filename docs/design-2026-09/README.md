시안은 **오늘 → RePlan → 상황 선택 → 대안 비교** 순서로 먼저 체험하면 된다. 상단 역할을 참여자로 바꾸면 승인 전 제안 흐름을 볼 수 있다. **기록 → 순간 기록 → 하루 기록 확정 → 에세이 초안**으로 기록에서 이야기까지 이어진다. 여행 선택을 바꿔도 세션 안에서는 기록이 유지되며, 새로고침하면 초기화된다.

## 제품의 중심

**여행 전에는 큰 계획을, 여행 중에는 다음 행동을, 여행 후에는 우리 이야기를 보여준다.**

큰 계획은 도시 이름만 적은 카드가 아니다. 거점·숙박일·핵심 경험·고정 예약·이동 연결·준비 과제를 하나로 묶는 계획 단위다. 이 안에서 세부 일정을 조정하며, 계획과 실제 경험은 서로 연결된 별도 데이터로 보존한다.

| 여행 단계 | 기본 화면 | 대표 행동 |
| --- | --- | --- |
| 출발 전 | 큰 계획 | 도시·박수·핵심 경험 확정하기 |
| 현장 | 오늘 | 다음 행동 확인 / 계획 바꾸기 / 순간 남기기 |
| 하루 마감 | 기록 | 실제로 한 일 확인하고 하루 확정하기 |
| 여행 후 | 우리 이야기 | 확정 기록으로 에세이 초안 만들기 |
| 일상 | 평생 여행장 | 지난 여행 찾기 / 다음 여행 구상하기 |

## 시안의 범위

시안의 장소명은 참고 여행의 맥락을 차용했다. 일정·참여자·시간·대체안·기록은 사용 흐름을 보여주는 가상 예시다. 완료 표시가 실제 방문 이력을 뜻하지 않는다. 실시간 날씨·길찾기·요금·예약 가능 여부를 조회하지 않는다. 실제 LLM·서버·공동편집 연결은 없으며 브라우저 메모리에서 체험한다. 새로고침하면 초기화된다.

시안은 현재 앱의 저장 키와 데이터를 읽거나 쓰지 않는다. 참고 시트의 여권번호·예약번호·개인 정산값은 포함하지 않았다. 참고 시트 자체도 수정하지 않았다.

## 이번 설계의 결정

1. 안정적인 4개 여행 내부 메뉴: **큰 계획 / 오늘 / 기록 / 준비**. 지출은 오늘의 빠른 입력과 준비의 공금 화면에서 접근한다. 동행자는 여행 헤더에서 바로 접근한다.
2. 출발 전에는 전체 도시 흐름을 먼저 만들고, 그다음 날짜·이동·예약을 구체화한다. 처음부터 빈 30분 시간표를 채우게 하지 않는다.
3. AI 출력은 계획 후보다. 검증된 사실·추정치·확인 필요를 구분하고, 위험·예약·이동 제약이 해결되지 않으면 확정 준비 상태로 표시하지 않는다.
4. RePlan은 완료·진행 중·고정 예약을 보호한 변경 제안이다. 단순 순연과 AI 실패 시 자동 덮어쓰기도 동일한 검토 계약을 따른다.
5. 개인 기록과 공동 계획의 소유권을 분리한다. 실시간 공동편집에는 인증·권한·공유 저장소를 추가한다. 개인 모드는 로컬 작성부터 시작한다.

기존 [UI/UX 명세](../ux-blueprint.md)와 [확장 아키텍처](../architecture-vnext.md)의 후속 구체화다. 구현 상태를 그 문서의 완료 항목으로 소급하지 않는다.
