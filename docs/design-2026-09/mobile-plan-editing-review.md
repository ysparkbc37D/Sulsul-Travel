# 큰 계획 편집·부분 재생성·모바일 탐색 개선 계획

작성일: 2026-09-10. 검토 기준: v1.3.0 / `ce04dfd`, 사용자 첨부 화면과 현행 소스. 구현 반영: v1.3.1.

이 문서는 설계·수용 기준이자 v1.3.1 구현 기록이다. v1.3.1에서 구간 상세 화면, 구간 메타 편집, 선택 범위 RePlan, 범위 밖 변경 차단, 완료 일정 접기, History API 복귀, 안전 영역과 고정 시트 조작부를 반영했다. 구간 추가·순서 변경, 서버 기반 공동편집, 안정적 스팟 ID 패치는 다음 단계로 남는다.

## 1. 결론

큰 계획을 **요약 카드 목록 → 구간 상세 보기 → 구간 편집 → 선택 범위 재생성 검토**로 바꾼다. 목록 아래에 전체 시간표를 길게 붙이는 구조를 기본 동선에서 제거한다. 긴 편집은 모바일 전용 상세 페이지로 열고, 짧은 선택만 시트로 처리한다.

보기와 편집의 목적을 분리한다. 계획 확정은 미래 계획의 승인이고, 방문 완료는 실제 경험 확인이다. 계획을 확정했다고 방문 완료로 바꾸지 않는다.

## 2. 확인된 문제와 원인

| 문제 | 소스·화면 근거 | 개선 결정 |
| --- | --- | --- |
| 큰 계획 날짜·숙소·거점 편집이 없음 | `buildPlanBlocks()`는 매번 `trip.days`를 추론해 임시 묶음을 만든다. 영속 block ID·구간 폼이 없다 | 독립 PlanBlock과 편집 초안을 도입 |
| 카드를 누르는 동작이 불명확 | `renderBigPlanTab()`의 article에는 진입 행동이 없고 작은 버튼만 있다 | 카드 제목·주 영역을 상세 진입 링크로 제공, 편집은 별도 버튼 |
| 세부 진입 후 긴 목록에 묻힘 | `openPlanBlock()`은 전역 펼침 상태를 바꾸고 전체 시간표의 `day-body`로 스크롤한다 | 선택 block의 날짜·일정만 렌더링하는 상세 화면 |
| 이전 화면·스크롤로 복귀 불가 | `switchTab()`은 항상 top 120으로 이동; 앱 탐색용 `pushState`/`popstate` 없음 | 화면 이력과 스크롤·포커스를 함께 복원 |
| 설정·튜닝 닫기와 저장 접근이 어려움 | `.sheet-box`에 max-height는 있으나 공통 본문 스크롤 계약 없음. 설정창 자체에 overflow-y-auto. `openModal()`은 body 스크롤 잠금만 수행 | 고정 제목/본문 스크롤/고정 행동의 공통 셸 |
| 하단 시스템 영역과 충돌 의심 | `viewport-fit=cover` 사용, safe-area 여백 및 키보드 viewport 대응 없음 | 안전 영역·키보드 대응. 실제 Android/iOS 증상은 별도 재현 |
| 부분 재생성 경계가 약함 | `executeScheduleTuning()`은 전체 days를 AI에 보내 전체 days를 받는다. 보호 검사는 제목·시간·boolean 위주 | 선택 item ID 범위의 patch만 허용, 범위 밖 수정은 코드로 차단 |
| 완료 화면이 편집 화면과 구분되지 않음 | 남은 항목 중심 카드 요약과 일정 완료 boolean만 사용 | 계획 상태와 방문 상태를 분리하고 완료 기록 전용 보기 제공 |
| 모바일 클릭 영역·대비 부족 | 첨부 화면의 옅은 녹색 상세 버튼, 소스의 28~32px 아이콘 버튼과 9~12px 부가 글씨 | 상태별 대비와 44px 이상 터치 영역 확보 |
| 날짜·순서 변경 시 기존 기록 연결 위험 | 일정·일기가 배열 인덱스에 의존; 오늘 선택은 UTC 날짜 문자열 및 첫 미완료 항목 기반 | 안정적 ID 및 현지 날짜 모델로 이전, 수동 날짜 선택 유지 |

앱 상단에는 이미 sticky 헤더가 있다. 다만 `html, body`의 overflow 설정과 모달의 별도 스크롤이 있어 실제 스크롤 소유자별로 확인해야 한다. 단순히 z-index를 올리는 것으로 해결하지 않는다. 첨부 정지 화면만으로 OS 홈·뒤로가기 버튼 자체가 차단됐다고 단정하지 않는다.

## 3. 화면 구조

```text
큰 계획 목록
 ├ 전체 여행 설정: 기간·인원·속도·예산
 ├ 큰 계획 카드: 도시 / 기간 / 숙소 / 핵심 경험 / 준비 상태
 │    카드 주 영역 → 해당 구간 상세
 │    구간 편집 → 해당 구간 편집
 └ 구간 추가 / 순서 변경

구간 상세: ← 큰 계획     로스앤젤레스     ⋯
 [개요] [일정] [예약·이동] [기록]
 선택 구간의 날짜와 일정만 스크롤
 하단: [구간 편집] [이 구간 재생성]

구간 편집: ← 상세        구간 편집       임시저장 상태
 기간·숙소·경험·이동 조건 입력
 하단: [취소] [변경 검토]

변경 검토: ← 편집        바뀌는 내용 확인
 날짜·박수·이동·예약·경험의 전후 비교와 충돌
 하단: [편집 계속] [변경 확정]
```

### 큰 계획 카드

- 목록에서는 ① 목적지·기간 ② 핵심 경험 1~3개 ③ 숙소 ④ 다음 이동 ⑤ 결정 필요 순서로 읽는다. 단순 공항 수속 3개를 핵심 경험으로 채우지 않는다.
- 계획 상태: 작성 중 / 계획 확정 / 재검토 필요. 별도로 방문 완료 수와 건너뜀 수를 표시한다.
- 목록 필터: 전체 / 준비 중 / 여행 중 / 다녀온 구간. 완료 카드를 자동 삭제하거나 숨기지 않는다.
- `보호 0` 대신 `고정 예약 2 · 방문 완료 3`처럼 의미가 분명한 문구를 사용한다. `다음 거점 이동 확인`은 실제 연결 상세로 열리는 행동으로 만든다.
- 카드 주 영역은 키보드로도 열 수 있는 링크로 구현한다. 링크 안에 편집 버튼을 중첩하지 않는다. 드래그 정렬 외에 위/아래 이동 버튼을 제공한다.

### 구간 상세와 완료 보기

- 상세 기본값은 읽기 모드다. 헤더에는 상위 화면, 구간명, 문맥 메뉴를 항상 보인다. 앱 설정은 문맥 메뉴에서 접근할 수 있으며 닫으면 같은 상세 위치로 돌아온다.
- 일정 안의 항목을 누르면 장소·시간·체류·예약·메모·팁을 본다. 짧은 수정은 시트, 긴 일정 폼은 편집 페이지를 사용한다.
- 미래 계획이 확정되어도 `계획 수정` 가능. 기존 확정본은 유지하고 수정 초안만 생성한다.
- 다녀온 구간은 실제 방문·사진·메모·지출을 먼저 보여준다. 원래 계획은 별도 펼침으로 비교한다. 완료 시각 정정은 기록 수정 이력으로 남긴다.
- 일부 완료 구간은 남은 일정만 재생성한다. 모든 일정이 완료/건너뜀인 구간은 재생성 대신 `기록 보완`과 `다음 여행에 복사`를 제공한다. 건너뜀을 방문 완료로 세지 않는다.

## 4. 여행 전 큰 계획 편집

| 범위 | 편집 항목 | 저장 전 영향 검토 |
| --- | --- | --- |
| 전체 여행 | 출발·귀국일, 인원, 여행 속도, 예산 | 구간 날짜 범위, 고정 항공, 누락 날짜 |
| 구간 | 거점명, 기간/박수, 숙소, 핵심 경험, 교통 선호, 구간 예산 | 앞뒤 구간 이동·체크인·예약 |
| 하루 | 날짜, 휴식·출발/마감 시각, 경험 우선순위 | 구간 소속, 운영시간, 완료 기록 |
| 선택 일정 | 장소, 시작·종료, 체류, 예약, 비용, 고정 상태 | 중복 시간, 이동 여유, 날짜/시간대 |

기본 저장은 명시적 확정이다. 입력 중에는 원본과 분리된 초안을 기기에 임시 저장한다. 저장 실패 시 실패 상태와 입력을 유지하고 성공을 표시하지 않는다.

기간 변경 예: LA 2일→3일. 즉시 전체 날짜를 미루지 않는다. `다음 구간 1일 축소 / 이후 구간 순연 / 전체 여행 1일 연장`의 영향을 비교한다. 고정 항공·호텔과 충돌하는 선택지는 자동 확정할 수 없다. 사용자가 선택한 날짜 이동도 변경안 범위에 포함한다.

구간 삭제는 연결된 실제 기록을 삭제하지 않는다. 방문 기록이 있는 구간은 보관 또는 미래 일정만 제거한다. 분리/합치기는 후속 작업으로 두고, 1차 편집에서는 구간 추가·수정·순서 변경을 우선한다.

## 5. 선택 범위 재생성

`대상 선택 → 변경 조건 → 전후 비교 → 확정`의 흐름이다. 구간에서 시작하면 기본 범위는 해당 구간의 미완료·비고정 일정이다. 여행 중 Today에서는 현재부터 오늘 끝까지가 기본값이다.

1. 범위: 이 구간 전체 / 선택 날짜 / 선택 일정. 실제 변경 가능한 항목 수를 보여준다.
2. 조건: 추가한 1일, 숙소 변경, 비·휴식·지연, 꼭 유지할 경험, 예산 등. 기존 수동 편집 항목은 기본적으로 유지하며 재생성 대상에 넣으려면 직접 선택한다.
3. 생성: 앞뒤 이동·고정 예약은 읽기용 문맥으로 전달하고, 변경 가능한 ID 목록을 별도로 전달한다.
4. 검증: 범위 밖 수정·삭제, 완료/진행 중/고정 항목 훼손, ID 중복·누락, 불가능한 시간·이동을 검사한다. 운영시간·요금 출처가 없으면 확인 필요다.
5. 비교: 추가/변경/제외 항목, 날짜·예산 영향, 보존 항목을 요약한다. 부분 채택은 연결 이동도 재검증한다.
6. 적용: 생성 당시 revision과 현재 revision을 비교하고 한 번 저장한다. 충돌 시 원본과 편집 초안을 모두 유지한다. 성공 후 진입했던 구간과 날짜로 돌아온다.

생성 중 사용자가 다른 구간을 수정하면 늦게 도착한 응답이 새 원본을 덮지 않는다. 중복 승인·오프라인·시간 초과·저장 실패도 같은 계약을 따른다. AI 실패 시 `기존 계획 유지 / 수동 편집 / 시간 조정안 검토`를 제공한다. 단순 시간 이동을 동선 최적화 성공으로 표현하지 않는다.

되돌리기는 최신 계획 변경의 역 patch로 처리한다. 이후 새 방문 기록이나 다른 수정이 있으면 되돌림 가능 여부를 다시 검증하며 여행 전체를 과거 snapshot으로 교체하지 않는다.

## 6. 모바일 탐색·스크롤·안전 영역

### 하나의 탐색 계약

- 앱 뒤로가기와 브라우저/Android 뒤로가기는 같은 화면 이력을 따른다. `검토 → 편집 → 구간 상세 → 큰 계획 목록`으로 한 단계씩 돌아온다.
- 큰 계획 목록으로 돌아오면 선택 카드, 목록 스크롤, 필터, 포커스를 복원한다. 중첩 설정을 닫으면 이전 상세의 입력값·스크롤을 복원한다.
- `홈`은 내 여행장으로 가는 별도 행동이다. OS 홈 제스처를 앱 탐색으로 가로채지 않는다. 앱 루트에서 브라우저 뒤로가기를 인위적으로 막지 않는다.
- 진입 시 history 상태를 만들고 popstate로 복원한다. 뒤로가기에서 반복 push로 사용자를 가두지 않는다. history에는 화면 ID만 넣고 폼·키·개인 기록을 넣지 않는다. 공유 링크 hash와 충돌하지 않게 URL 계약을 정한다. 근거: [MDN History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API).
- 입력 변경은 임시 초안으로 보존한다. 확정하지 않은 변경이 있으면 `계속 편집 / 초안 보관 후 나가기 / 변경 버리기`를 제공한다. 모든 Back 경로에서 같은 규칙을 적용한다.

### 화면 셸

- 모바일 상세/편집은 `고정 헤더 + 스크롤 본문 + 고정 하단 행동` 3영역으로 만든다. 각 화면의 스크롤 영역은 하나다. 목록 전체와 상세를 동시에 펼쳐 두지 않는다.
- 긴 설정·튜닝도 같은 셸을 적용한다. 제목/뒤로가기/닫기는 본문과 함께 사라지지 않는다. PC에서는 같은 데이터를 우측 상세 패널이나 대화상자로 표시한다.
- 상위 메뉴 4개는 최상위 여행 화면에서 유지한다. 편집 중에는 하단 공간을 취소/검토/저장에 사용하고 상위 메뉴를 겹쳐 그리지 않는다.
- `100dvh` 기반 높이와 fallback, `min-height:0` 본문, 실제 스크롤 소유자별 overflow를 명시한다. 키보드가 열리면 visual viewport를 반영해 입력과 저장 행동을 볼 수 있게 한다.
- `env(safe-area-inset-top/bottom/left/right)`에 기본 여백을 더한다. 하단 행동 높이만큼 본문 여백도 확보한다. 안전 영역 안에 작은 버튼을 놓지 않는다. 근거: [WebKit safe-area 안내](https://webkit.org/blog/7929/designing-websites-for-iphone-x/).
- 시트는 짧은 선택만 사용하고 최대 한 단계만 겹친다. 긴 폼 위의 확인 대화상자를 제외한 중첩은 페이지로 전환한다. 모달 포커스 이동·가두기·Escape·호출 버튼 복귀 및 배경 inert를 공통 관리한다. 근거: [W3C Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

## 7. 함께 개선할 UI/UX

- 입력 본문 16px, 부가 정보 13~14px, 핵심 행동 높이 최소 44px를 제품 기준으로 정한다. 페이지 확대 제한을 제거하고 200% 확대를 확인한다.
- 옅은 민트 버튼은 밝은 배경에서 읽을 수 있는 진한 전경색으로 바꾼다. 테마 전역 `!important` 색상 덮어쓰기를 줄이고 카드/히어로/버튼의 토큰을 분리한다.
- `즉시 재배치`는 실제 동작에 맞게 `시간 조정안 보기`, AI는 `선택 일정 다시 만들기`로 바꾼다. `보호`, `룸코드`처럼 설명이 필요한 용어는 사용자 행동으로 표현한다.
- Today의 날짜 선택을 제공하고 여행지 현지 날짜를 기준으로 삼는다. 과거 미완료가 남아도 매번 Day 1로 되돌리지 않는다. 건너뜀 취소를 제공한다.
- 일정의 시간 문자열 정렬을 제거한다. 현재 범위 문자열과 날짜변경선 항목은 명시적 시간대·날짜가 없어 실제 순서가 뒤집힐 수 있다. 자정, +1일, 서쪽으로 이동하는 항공을 별도 검증한다.
- 큰 계획 편집 저장 시 카드·Today·지도·예약·기록 요약을 동일한 저장 결과에서 갱신한다. 전체 DOM 재생성으로 입력 포커스를 잃지 않게 한다.
- 첫 방문의 강제 설치 안내는 비차단 배너로 바꾼다. 일정 작성 전에 안내창을 닫는 행동을 요구하지 않는다.

## 8. 데이터·개발 구조

| 경계 | 추가/변경 내용 |
| --- | --- |
| `js/domain/plan-block.mjs` (신규 예정) | PlanBlock `{id, tripId, title, place, startLocalDate, endLocalDate, timezone, itemIds, lodging, incomingTransfer, priorities, budget, planStatus}`; 한 날짜에 여러 block 허용 |
| 일정·경험 ID | day/spot에 안정적 ID; plan item과 실제 experience 분리. 날짜 변경으로 일기·사진 소유권이 이동하지 않음 |
| `js/application/plan-editing.mjs` (신규 예정) | 원본/편집 초안/검토 변경안, 저장 상태, 날짜 변경 영향 계산 |
| `js/domain/replan.mjs` | scope item IDs, baseRevision, operations, 보존 항목, 경계 이동 검증. 제목 비교 대신 ID와 보호 필드 비교 |
| `js/application/orchestration.mjs` | 범위별 AI job, 늦은 응답·취소, 적용 이전 재검증 |
| 탐색·모달 셸 (신규 모듈) | route stack, scroll/focus 복원, draft 복원, viewport·safe-area |
| 기존 repository | 모든 편집을 단일 저장 경계로 통합. 저장 실패 예외를 UI에 전달. 다른 탭 변경 감지 및 적용 전 영속 revision 확인 |

기존 추론 함수는 최초 마이그레이션의 후보 생성에만 사용한다. 사용자가 저장한 거점 이름·기간은 다음 렌더링에서 재추론하지 않는다. 마이그레이션은 기존 데이터 보존본과 schemaVersion을 두고 멱등으로 수행한다. ID가 없는 사진·일기는 이전 인덱스→새 ID 매핑으로 연결하며 불명확한 항목은 확인 목록에 남긴다.

로컬 저장 경계 개선이 서버 공동편집을 의미하지 않는다. 다기기 공동편집은 별도 인증·서버 revision·권한 단계에서 연결한다.
