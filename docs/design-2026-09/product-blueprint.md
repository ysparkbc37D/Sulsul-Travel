# 제품·UI/UX 설계 — 큰 계획에서 평생 여행장까지

## 1. 제품 약속

술술트래블은 **함께 결정하고, 현장에서 유연하게 바꾸고, 실제 경험을 평생 간직하는 여행 동반자**다. 관광지 수를 최대화하는 것보다 일행이 무리 없이 소중한 경험을 누리는 것을 우선한다. ‘최적’은 이동시간만의 최솟값이 아니라 예약·예산·휴식·동행자 요구 안에서 선택한 실행 가능한 계획을 뜻한다.

대표 사용자는 계획 담당자, 현장에서 함께 수정하는 동행자, 기록 위주 참여자다. 앱에 익숙하지 않은 동행자도 초대받은 여행에서 ‘오늘 어디 가는지 / 무엇을 준비해야 하는지 / 어떻게 의견을 내는지’를 바로 이해해야 한다.

## 2. 정보 구조

```text
내 여행장
 ├ 진행 중 여행 → 오늘
 ├ 예정 여행 → 큰 계획
 ├ 지난 여행 → 기록 / 에세이
 └ 다음에 가고 싶은 곳 → 새 큰 계획의 재료

여행 내부: [큰 계획] [오늘] [기록] [준비]
 ├ 헤더: 여행명 · 현지 날짜 · 저장/동기화 상태 · 동행자
 ├ 큰 계획: 거점 카드 · 연결 이동 · 전체 경로 · 버전 비교
 ├ 오늘: 지금/다음 · 남은 일정 · 계획 바꾸기 · + 순간 기록
 ├ 기록: 날짜별 확정 경험 · 사진/메모 · 개인/공동 이야기 · 에세이
 └ 준비: 예약·티켓 · 체크리스트 · 공금/지출 · 문서 · 여행 설정
```

주 메뉴의 이름과 위치는 고정한다. 여행 단계에 따라 처음 열리는 화면과 대표 행동만 바꾼다. 단계 전환은 사용자가 되돌릴 수 있다. 준비 메뉴는 출발 후에도 같은 위치에 남아 바우처·숙소·공금을 찾을 수 있다. 지출 기록은 오늘의 ‘+’에서도 바로 열린다.

## 3. 큰 계획 카드

큰 계획 카드의 기본 단위는 **한 거점에 머물며 달성할 경험 묶음**이다. 여러 도시를 당일 이동하는 경우 한 날짜에 카드가 여러 개일 수 있고, 한 도시에서 3박하면 카드 하나에 여러 날짜가 들어간다. ‘날짜 카드’와 ‘거점 카드’를 혼동하지 않는다.

| 항상 보이는 정보 | 펼치면 보이는 정보 |
| --- | --- |
| 도시·지역, 현지 기간/박수 | 도착·출발 장소, 숙소 체크인/체크아웃 |
| 이번 구간의 핵심 경험 1~3개 | 관광·식사·휴식 후보와 우선순위 |
| 대표 숙소 또는 숙소 미정 | 객실 구성, 짐 보관, 주차·마지막 도보 |
| 다음 거점까지 이동 수단·예상 범위 | 교통편, 탑승/환승 여유, 출처·확인 시각 |
| 결정 필요 1~2건 | 예약 기한·담당자·예약 상태·비용 영향 |
| 계획 상태와 동행자 의견 수 | 상세 날짜 일정, 변경 이력, 댓글 |

대표 행동은 ‘세부 일정 보기’. 보조 행동 ‘구간 수정’, ‘의견’. 그림과 사진은 거점을 인식하는 데 쓰며 첫 화면에서 정보를 밀어내지 않는다. 고정 예약은 잠금 아이콘+‘시간 고정’, 미검증 정보는 ‘확인 필요’ 텍스트로 표시한다.

예시 구조(실제 예약·방문 확정 아님):

- 세부: 도착·이동 → 북부 리조트 체류 → 시내 체류 → 귀국. 휴식·다인 객실·단체 이동이 핵심.
- 대만: 타이베이 도착 → 북동부 이동·지우펀 숙박 → 타이베이 체류·귀국. 입장 마감·차량 반납·숙박 연결이 핵심.
- 윈난: 경유 → 쿤밍 → 다리 → 리장 → 호도협/샹그릴라 → 귀로. 철도·버스·짐 보관·적응/휴식이 핵심.

### 큰 계획 설계 흐름

1. 목적지·기간·인원만 입력한다. 기간 미정이면 월/박수로 시작한다.
2. 일행의 여행 속도, 꼭 하고 싶은 경험, 이동 수단, 예산 범위, 휴식 요구를 선택한다. 항공·숙소가 있으면 고정한다.
3. AI가 ‘여유 중심 / 이동 절약 / 경험 중심’ 등 서로 다른 후보 2~3개를 제시한다. 정보가 없으면 빈칸과 필요한 질문을 표시한다.
4. 사용자가 도시 순서·박수·핵심 경험을 확정한다. 이후 해당 범위에서 상세 일정·예약 과제를 만든다.
5. 확정 전 준비 점검: 날짜 충돌, 마지막 입장, 교통 연결, 예약 필요, 휴식, 필수 확인 정보를 한 목록으로 보여준다.

시트/PDF 가져오기는 별도 진입점이다. ‘원본 확인 → 날짜/항목 후보 → 충돌 선택 → 큰 계획 미리보기 → 가져오기’로 구성하며 AI가 원본에 쓰지 않는다. 오류가 있는 필드만 다시 입력하게 한다.

## 4. 현장의 ‘오늘’

첫 화면 순서: 현지 날짜/거점 → 중요한 변화 → 지금·다음 행동 → 남은 일정 → 순간 기록. 과거 완료 항목은 접어 두지만 언제든 다시 볼 수 있다. 현재 위치 권한이 없으면 사용자가 거점/현재 장소를 고른다.

각 일정은 **장소·시간 / 이동 / 완료·건너뜀 / 기록**을 같은 맥락에서 제공한다. 상세를 열면 체류시간, 예약, 담당자, 준비사항을 본다. 이동 카드는 ‘차량 40~55분 + 주차/도보 15분, 조회 시각’처럼 보여준다. 데이터가 없으면 ‘이동시간 확인 필요’라고 쓴다.

‘방문 완료’는 실제 시각과 확인한 사람을 가진 기록을 만든다. 계획 시간이 지났다는 이유로 완료하지 않는다. 방문 완료 후 한 줄 기록은 선택이며 건너뛰어도 다음 행동을 막지 않는다. 같은 일정에 참여하지 않은 동행자를 방문자로 자동 지정하지 않는다.

### RePlan: 3단계

**① 상황 → ② 대안 비교 → ③ 적용 또는 동행자에게 제안**

- 빠른 상황 버튼: 늦어졌어요 / 비가 와요 / 쉬고 싶어요 / 예약이 바뀌었어요 / 여기 가고 싶어요. 자유 입력도 지원한다.
- 변경 범위 기본값은 ‘현재부터 오늘 끝까지’. 다른 날짜·거점까지 영향을 주면 별도 표시한다.
- ‘완료한 일정’, ‘현재 진행 중’, ‘고정 예약’은 유지한다. 불가피하게 예약을 바꿔야 하면 자동 해제가 아니라 별도 과제로 만든다.
- 기본 대안은 2개, 많아도 3개. 변경 장소·시각·추가 비용·이동/보행 부담·빠지는 경험·확인할 사항을 같은 순서로 비교한다.
- 선택적 항목 채택은 종속된 이동도 함께 검증한다. 앞뒤 연결이 깨지면 확인 필요 상태로 남긴다.
- 성공 토스트 대신 ‘어떤 일정이 바뀌었는지’와 되돌리기 제공. 실제 완료 기록은 되돌리기의 대상이 아니다.

단순 30분 순연도 같은 검토를 거친다. AI 오류/오프라인에서는 기존 일정 유지, 수동 시간 수정 및 로컬 검증만 제공한다. 새 연결 시각·영업 여부를 확인하지 못한 제안을 안전하다고 표시하지 않는다.

## 5. 함께 결정하는 방식

| 역할 | 할 수 있는 일 | 제한 |
| --- | --- | --- |
| 여행 관리자 | 멤버/역할, 공통 규칙, 백업·아카이브 | 다른 사람의 비공개 원문 열람 권한 없음 |
| 일정 조정자 | 공동 계획 확정, RePlan 적용 | 예약 구매·취소는 별도 외부 작업 |
| 참여자 | 후보·의견·변경 제안, 본인 기록, 담당 과제 완료 | 공동 고정 일정 변경은 조정자 확정 |
| 열람자 | 허용된 공동 계획·기록 보기 | 쓰기 불가 |

기본은 관리자가 조정자를 겸한다. 소규모 여행은 모든 참여자에게 조정자 역할을 줄 수 있다. **구현 목표 정책**이며 새 계정 서비스는 이번 시안에서 만들지 않았다.

- 카드 댓글은 해당 카드/일정/제안에 붙는다. 동의 수는 참고 정보이며 다수결만으로 자동 적용하지 않는다.
- ‘잠시 나눠 여행’은 하위 그룹별 일정과 재합류 장소·시각을 갖는다. 단순히 일정을 숨기는 기능으로 대체하지 않는다.
- 개인 메모·사진은 작성자가 공개 범위를 고른다. 공동 계획 편집과 개인 기억의 편집 권한은 다르다.
- 온라인 상태는 서버 응답에 근거한다. ‘내 기기에 저장됨 / 전송 대기 / 동행자와 동기화됨 / 충돌 확인 필요’를 구분한다.
- 여행을 나간 사람의 개인 기록은 본인이 보유할 수 있다. 공동 기록은 출처·권한에 따른 스냅샷 정책을 두며 탈퇴·회수 동작을 명시한다.

## 6. 기록에서 에세이까지

여행 계획은 ‘할 예정’, 경험 기록은 ‘실제로 한 일’, 에세이는 ‘기록을 엮은 글’이다. 이를 별도 화면 객체로 구분하되 같은 카드·날짜에서 이어진다.

1. 사진/메모/지출/음성 변환 결과를 Moment로 저장한다. 텍스트 먼저 저장하고 미디어 업로드는 별도 상태로 보여준다.
2. 하루 마감에서 방문·건너뜀·미확인 항목과 사진 묶음을 확인한다. 미확인은 임의로 방문으로 바꾸지 않는다.
3. 하루를 확정하면 읽기용 DaySummary를 만든다. 수정은 새 버전으로 남는다.
4. 여행 종료 후 ‘내 여행기 / 우리 여행기’를 선택한다. 공동 글에는 참여자가 공유를 허용한 기록만 쓴다.
5. AI가 목차 → 장별 초안 → 사실 검토 → 편집본 순으로 생성한다. 문단에서 근거 기록을 열 수 있다. 감정·대화·날씨를 창작하여 사실처럼 삽입하지 않는다.
6. 사용자가 승인한 에세이를 여행장에 보관하고 Markdown/PDF/사진 포함 원본 백업을 내보낸다. 다시 생성해도 수동 편집본을 덮지 않는다.

빈 여행에서 ‘에세이 작성’은 기록 추가를 안내한다. 단체 사진 자동 얼굴 인식이나 지속 위치 수집을 기본값으로 요구하지 않는다.

## 7. 평생 여행장

홈은 진행 중 여행 하나를 크게, 예정 여행을 그다음, 지난 여행을 연도별 책장으로 보여준다. 연도·목적지·함께한 사람·기억 키워드로 찾는다. 장소 통계는 확인된 방문에서, 여행수는 여행 객체에서 각각 계산한다. 예제·미방문 후보는 개인 통계에 포함하지 않는다.

관계는 ‘같이 계획했던 사람 / 같이 방문한 사람 / 기록을 공유받은 사람’으로 구분한다. 지난 여행의 ‘다음에도 하고 싶음’ 표시가 새 계획의 선호를 돕되, 과거의 예산·체력·동행자를 영구 프로필로 고정하지 않는다.

데이터 이동성과 복구는 핵심 제품 기능이다. 단순 ‘클라우드 저장’ 배지 대신 마지막 검증된 백업 시각, 미디어 포함 여부, 복원 가능 버전을 표시한다. 국가·연도별 수천 건 기록은 페이지 조회와 검색 인덱스로 다룬다.

## 8. 시각·반응형 기준

- 따뜻한 미색 배경, 짙은 숲색 본문/주요 행동, 앰버는 AI 제안·확인 필요에 사용한다. 금색 그라데이션과 강한 그림자의 반복을 줄인다.
- 본문 16px, 부가 정보 13~14px. 한글 `word-break: keep-all`, 긴 주소·URL은 `overflow-wrap: anywhere`. 핵심 버튼은 텍스트를 포함한다.
- 8px 간격 체계, 카드 16~20px 여백, 반경 16~20px. 보조 정보를 접어 읽는 순서를 만든다.
- 모바일: 상단 여행 맥락, 본문 단일 열, 하단 4개 메뉴. 상세는 하단 시트. 360px에서도 카드 내용과 44px 터치 영역이 겹치지 않음.
- PC: 왼쪽 여행 전환, 가운데 큰 계획/하루, 오른쪽 선택 항목 정보·준비. 지도는 계획을 고칠 때 인접하고 쓰지 않을 때 숨김.
- 시각적 목적 사진은 여행당 대표 1장과 기록 사진 위주. 현재 시안의 그림은 장식용 도시 삽화이며 실제 지도가 아니다.
- 모달: 제목, 포커스 이동/가두기, Escape·닫기, 원래 버튼으로 포커스 복귀. 색 외 상태 텍스트. 동적 저장 결과 `aria-live`.
- 실제 출시 전 키보드, 스크린리더, 200% 확대, 360/390/768/1280px, 대비 측정. 시안 검증만으로 접근성 적합성 전체를 보증하지 않는다.

## 9. 사용자 검증 과업

초기 목표치이며 아직 사용자 실험으로 입증되지 않았다. 5~7명, 계획 담당·동행자·초보 사용자를 섞어 관찰한다.

| 과업 | 완료 기준 |
