# 사진 보관 용량 최적화

2026-11-03 · v2.0.0. 저장소의 순차 자릿수 규칙에 따라 v1.9.9 다음을 v2.0.0으로 표시한다.

## 새 사진

새 사진은 공통 압축 모듈을 거친다. 기록·물건 사진은 긴 변 1280px, 약 160KB를 목표로 한다. 사진을 늘리거나 자르지 않으며 JPEG·WebP 중 실제로 더 작은 결과를 사용한다. 작은 JPEG·PNG·WebP를 다시 크게 만들지 않는다. 썸네일은 긴 변 320px, 약 40KB가 목표다.

영수증 자동 입력과 지출의 글자 우선 첨부는 문서 기준을 쓴다. 일반 문서는 긴 변 2400px를 기준으로 하되 긴 영수증은 짧은 변 1000px를 우선해 글자 폭을 유지한다. 예를 들어 1800×9000은 1000×5000으로 줄이며 무조건 800px 장축으로 축소하지 않는다. 약 180KB는 목표값이다. 가독성을 버리고 용량을 강제로 맞추지 않으므로 긴 문서는 더 커질 수 있다. 출력은 16MP·단일 축 16384px를 넘기지 않고, 이를 초과하는 긴 문서는 나누어 선택하도록 안내한다.

압축은 사진을 순차 처리하고 시간 제한·취소·20MB 입력 제한을 적용한다. 원본은 브라우저 밖으로 전송하지 않는다. 영수증 OCR을 실행할 때의 기존 AI 전송은 별도 사용자 기능이다.

영수증 AI에는 압축 결과의 실제 MIME 형식을 전달한다. JPEG로 고정하지 않는다. [Google의 지원 이미지 형식](https://ai.google.dev/gemini-api/docs/image-understanding)에 PNG·JPEG·WebP가 명시되어 있다.

## 등록된 사진

설정 → 데이터·관리 → **사진 용량 최적화**에서 전체 여행 또는 한 여행을 고른다. 용도별 기준은 지출을 문서로, 일기·일정·순간 기록을 일반 사진으로 처리한다. 모두 글자 우선도 선택할 수 있다.

미리보기는 원문을 바꾸지 않는다. 사진 데이터의 예상 절감량과 압축 후 이미지를 준비하고, 기존/압축 후 전환과 실제 크기 보기를 제공한다. 적용할 사진만 선택한다. 이미 목표 용량 이하거나 절감이 10% 미만인 사진은 재압축하지 않는다. 썸네일까지 합산해 전체 데이터가 증가하는 교체도 제외한다. 외부 URL 사진은 다운로드하지 않고 그대로 둔다.

적용할 때 원래 저장 문서·메모리·사진 출처·안정 식별자가 같은지 검사한다. 지출 보관본 준비와 JSON 저장이 성공한 뒤에만 결과를 채택한다. 실패·다른 창의 변경·미리보기 취소는 원본과 글을 보존한다. 사진 순서·대표사진 인덱스·사진이 붙은 일정·원문·AI 승인문·미지 필드를 유지한다.

옛 썸네일·Blob은 새 사진과 연결하지 않는다. 사진 교체 후에는 이번 교체로 사용하지 않게 된 ID만 정리한다. 모든 여행의 공유 참조와 미저장 사진 초안의 참조를 보호한다. 다른 작업에서 방금 준비한 업로드를 일괄 삭제하지 않는다. 저장 성공 후 정리가 실패하면 저장과 정리 결과를 구분하며 재시도할 수 있다.

손실 압축한 사진에서 카메라 원본 화질로 되돌릴 수는 없다. 필요하면 미리보기의 원본 백업 기능을 사용한다. 자동 테스트나 작은 이미지의 선명도 기준이 모든 실제 영수증의 글자 판독을 보증하지 않는다. 확대 비교가 최종 판단이다.

## 검증

개인 자료를 쓰지 않고 한국어·영문·금액이 있는 합성 영수증, 긴 영수증, 풍경, 세로 사진, 작은 JPEG를 검사했다. 원본을 고품질·질감이 많은 조건으로 만든 결과이므로 절감률을 일반 사용자의 이미 압축된 사진에 적용할 수 없다.

| 합성 자료 | 입력 | 출력 | 확대 크기 |
| --- | ---: | ---: | --- |
| 영수증 | 1,961,033B | 164,666B | 1600×2400 |
| 긴 영수증 | 6,737,100B | 240,352B | 1000×5000 |
| 풍경 | 3,472,056B | 121,302B | 1280px 긴 변 |
| 세로 사진 | 2,235,579B | 70,584B | 1280px 긴 변 |

네 모서리·종횡비·문서 97개 행의 명암 특징을 검사하고 금액·한국어 확대 비교를 직접 열었다. OCR 정확도 검사는 아니다. 작은 기존 JPEG 1744B는 원문 바이트를 유지했다. 잘못된 파일·취소·시간 초과·너무 큰 캔버스도 별도 검사한다.

긴 영수증의 첫 압축은 240,352B였으며 2·3·4차 최적화는 모두 같은 바이트를 유지했다. 이 합성 사례에서는 목표 용량을 넘더라도 10% 이상 추가 절감되지 않아 반복 손실 압축하지 않았다.

실제 앱에서는 미리보기의 무변경, 선택 적용, 실패 재시도, 다른 창 충돌, 원문·대표사진·일정 연결, 새 페이지·백업 복원, 공유·미저장 사진 참조와 이전 보관본 정리를 확인한다. 실제 기기별 영수증의 판독률·사진 저장 공간은 별도 사용자 검토가 필요하다.

최종 단위 검사 225건과 실제 앱 사진 최적화 12개 흐름이 통과했다. 대상 여행·읽기 기준을 바꾸면 이전 미리보기의 적용을 막는 경계도 포함한다. 기존 일정·순간·지출 사진, 전체 백업, 뒤로가기와 구 서비스워커 업그레이드 회귀도 통과했다.
