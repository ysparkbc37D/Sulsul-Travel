# v1.7.9 — 통합 검토 A 단계 구현

기준: 2026-09-14. [v1.7.8 통합 검토](review-v1.7.8-2026-09-13.md)의 저장·공유·대비·출력 문제부터 수정했다.

## 사용자 행동 변화

- **일기 저장**: 실패하면 기존 저장 문서를 유지하고 입력창/날짜별 세션 초안을 보존한다. 다시 저장하거나 ‘글 파일 보관’으로 TXT를 내려받는다. 세션 초안은 브라우저 재시작을 견디는 영구 저장을 뜻하지 않는다.
- **사진 추가**: 읽기 시작 시 여행·날짜를 고정하고, 저장 실패나 날짜 변경을 알려 잘못된 날짜에 사진이 들어가는 것을 막는다.
- **완료/고정 토글**: 저장 실패 시 메모리 상태도 원복하며 성공 메시지를 표시하지 않는다.
- **여행 사본 보내기**: 일정·큰 계획·준비물은 기본 포함. 개인 일기/사진과 지출/환전/지갑 정보는 각 체크박스로 선택한다. 전체 백업과 별개다.
- **파일 공유**: Web Share의 파일 공유가 지원되면 OS 공유 창을 사용하고, 미지원/실패 시 JSON 다운로드로 전환한다. 사용자가 공유를 취소하면 다운로드를 강행하지 않는다.
- **링크 공유**: 2,000자 초과 또는 localhost이면 복사 대신 파일 전송을 안내한다. 2,000자는 제품의 보수적인 상한이며 모든 메신저가 그 이하를 지원한다는 보증은 아니다.
- **가져오기**: 내용/범위를 확인하고 사본 추가를 승인한 후 저장한다. 저장 실패 때 기존 목록과 URL 유지, 성공 때 URL 정리. 같은 새 링크는 shareId로 중복 감지한다. 과거 `ver + trip` 링크도 지원한다.
- **공유 데이터**: 큰 계획의 제목/숙소/우선 경험/메모/확정 상태와 0원 예산을 보존한다. 새 스키마보다 높은 버전, 잘못된 구조, HTML 포함 데이터, 지원하지 않는 사진 주소는 거부한다. 한 파일의 입력 제한은 20MB다.
- **밝은 상태 배지**: `travel-status`가 배경과 글자를 함께 관리한다. 여행 중 배지는 모던·라이트그레이·딥블랙 모두 8.57:1로 측정했다.
- **PDF**: 일정별 시간, 예정/방문 완료/건너뜀, 상세 설명을 출력한다. 없는 날씨와 감정·여행 날짜는 사실처럼 채우지 않는다. 제목·일정·일기 등 출력 텍스트와 사진 주소 처리를 보강한다. 인쇄에서는 보고서 외 화면을 숨긴다.
- **복원**: JSON/Gist는 저장 성공 전 현재 State를 교체하지 않는다. 전체 백업 복원은 교체 확인을 거치며 사본 파일 가져오기는 기존 여행에 추가한다.

## 구조

`js/domain/trip-transfer.js`는 DOM/저장소가 없는 공유 계약이다. PLAN_FIELDS와 MONEY_FIELDS를 한 곳에서 정의하고 스키마를 검증한다. 앱 버전과 공유 스키마 버전 1은 별개다. `js/presentation/trip-transfer-ui.js`가 링크/파일 UI와 기존 저장 repository를 연결한다. 새 스크립트는 SW 사전 캐시에 포함된다.

데이터를 먼저 복사→검증→저장→State 교체하는 경로를 공유 가져오기·일기·사진·복원에 적용했다. 기존 `st_trips_v2`와 AI 초안 승인/overflow 구조는 유지했다. 다음 단계에서 기능별 저장 명령을 더 모으고 IDB로 이전한다.

새 계약 테스트는 메타/예산 0 보존, 기본 비공개 범위 제외, 선택 금융 구조, 과거 링크, 잘못된 구조·신규 스키마·사진 주소 거부를 검사한다. 브라우저 테스트는 사용자 계정과 분리한 로컬 fixture에서 저장 실패/재시도, 날짜 이동 초안, 사본 실패/성공/중복, 파일 업로드/다운로드, 가상 배포 origin의 짧은/긴 링크, localhost 안내, PDF 사실 표시/escaping, 상태 배지 대비를 검사한다. 기존 320~1280px 상세 진입·편집·완료·뒤로가기 검사도 유지한다.

기존 테스트의 옛 캐시 버전 문자열과 RGB를 현행 동작에 맞췄다. 최소 일정 개수 검사는 현재 장기여행 3/일·일반 4/일 계약을 반영한 것이며 밀도 정책을 강화한 변경은 아니다. 날짜별 분할 AI 생성은 후속이다.

## 남아 있는 범위

- 하루 여러 글·일정별 기록, 미디어 Blob 이전, 여행 전체 에세이와 출처 연결은 B/C 단계.
- 짧은 인증 초대 링크와 실시간 공동편집은 선택형 서버가 필요한 D 단계. 현재 파일/URL은 독립 사본이다.
- 카카오톡·iOS·Android 실제 파일 수신/공유 창/키보드, 다페이지 PDF 인쇄의 실기기 확인은 별도로 필요하다.
- 메모리에만 남아 있는 수동 초안은 재시작 전에 저장 또는 TXT 보관해야 한다.
- 파일 상한(20MB) 이상의 사진 포함 전체 백업, 압축 payload의 스트리밍 처리, 전체 입력 렌더러 정비, IDB overflow와 전체 백업 복원 정책은 후속 저장소 작업에서 다룬다.
