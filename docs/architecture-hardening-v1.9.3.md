# v1.9.3 구조 보강과 검증

2026-10-11. 기준 공개 버전은 v1.9.2(`ac317b0`)이며, [수정 전 구조 검토](architecture-review-v1.9.2-2026-10-09.md)의 실제 결함을 우선 보강한다. 저장소 전체 재작성이나 장기 개선 계획 전체의 완료를 의미하지 않는다.

## 적용한 변경

| 영역 | 변경과 사용자에게 보이는 결과 |
| --- | --- |
| AI 계약 | 중복 전역 검증을 제거하고 `AiDraftValidation`을 생성·승인·직접 적용에 사용한다. 일수·일정 밀도·유효 날짜/시간·선택 범위를 검사한다. RePlan에서 완료·고정·기록 연결 일정의 ID·금액·메모를 포함한 필드를 보존한다. |
| AI 작업 | 실행 작업과 검토 작업의 ID를 구분한다. 실행/검토 중 두 번째 요청은 기존 초안을 가로채지 않는다. RePlan 연결 실패 시 기존 계획의 범위 안에서 시간 조정안을 만들고 로컬 대체임을 표시한다. |
| 로컬 초안 | 설정 복사본과 생성 결과를 분리하고 저장 뒤 이전 trip 참조를 계속 수정하지 않는다. 로컬 일정도 검토·승인 경로를 거쳐 기존 일정에 제안을 추가한다. 생성 중 여행 변경은 revision 검사로 중단한다. |
| 편집·삭제 | 일정 편집·일정/지출 삭제·초안 설정은 복사본 변경 → 검증 → 저장 → State 채택 순서다. 실패 시 원본과 편집 폼을 유지한다. 빠른 삭제 재시도 성공 후에도 확인창을 닫는다. |
| 탭 간 충돌 | 저장소에서 마지막으로 읽은 문서 원문과 현재 원문을 비교하여 오래된 탭의 전체 목록 덮어쓰기를 거절한다. 전체 백업 복원은 검토한 원문이 여전히 같을 때만 적용한다. |
| 기록 날짜 | 기존 회고에 ID·dayId·date를 보충한다. 일정 순서가 바뀌면 호환 숫자 키를 재배치하되 원래 날짜를 보존한다. 삭제한 날짜의 기록은 별도 보관하고 이야기/PDF에 남긴다. 작성 중 글과 비동기 사진도 안정 ID에 연결한다. |
| 설정 | 손상 환율 설정을 별도 보관하고 안전한 기본값을 읽어 여행·백업 화면의 시작을 유지한다. 맞춤 ARS MEP 환율도 보존한다. |
| 백업 | 파일/Gist가 같은 사진·보조 일기 수집·전체 백업 파싱·검토·복원 경계를 사용한다. Gist 읽기는 미리보기만 열고 적용 버튼에서 교체한다. 네트워크 대기 중 새 편집이 생기면 복원을 중단한다. |
| 공유 | 기본 공개 계획 DTO에서 개인 기록·사진·인증 필드를 먼저 제외한 뒤 검증한다. 제외된 개인 글의 기본 서식이나 평문 비교가 계획 공유를 막지 않는다. 공개 계획에 포함된 실행 가능한 HTML은 계속 거부한다. |
| 앱 캐시 | 외부 API·인증 헤더 요청은 캐시하지 않는다. 현재 버전의 명시된 공개 자산 URL만 읽고 저장한다. 변경된 저장·AI 모듈도 버전 쿼리와 precache 주소를 일치시킨다. 필수 셸 설치 실패 시 기존 워커를 유지하며, 새 HTML이 이전 셸을 덮거나 설치 자산이 다음 배포 내용으로 바뀌지 않도록 고정한다. |

## 검증

- 단위·정적 계약 검사 158개 통과. 전역 함수 중복도 검사하며 실제 앱의 최종 함수 실행을 별도로 확인한다.
- 격리된 HTTP/Edge 브라우저에서 두 탭 충돌, 손상 환율 부팅, 저장 용량 실패·재시도, 실제 편집/삭제 버튼, Gist 사진·보조 일기 왕복과 대기 중 새 글 보존을 검사한다.
- AI 28개 확인, 기록 날짜 연결 7개 확인, JSON 백업·복원 20개 시나리오가 통과했다. 로컬 엔진은 API 호출 없이 초안을 만들며 승인 전 원본을 유지한다.
- 서비스워커 실제 브라우저 확인 17개 통과. 새 배포의 필수 CSS 503, 버전이 다른 HTML, 같은 자산 주소의 서버 내용 변경 후에도 이전 설치본의 오프라인 전체 앱 진입을 검사했다.
- 추가 삭제 검토에서 가져온 ID `trip:other`의 보조 글이 `trip`의 접두사 삭제에 포함되는 문제를 확인했다. 키 접두사 대신 저장 레코드의 tripId를 정확히 비교하며 해당 회귀검사를 추가했다.
- 기존 모바일·예제·기록·가계부·협업 검토·여행기 출력과 오프라인 재시작을 함께 검사한다. 실제 사용자 여행·인증 정보는 검사 자료로 사용하지 않는다.
- 물리 휴대폰과 iOS 엔진, 실제 Google/Gist/Supabase 계정을 사용한 운영 검증은 수행하지 않았다. 서버 협업은 합성 응답으로 검사하며 실제 다중 계정 RLS 검증과 구별한다.

주요 실행 명령은 `npm test`, `npm run test:structure`, `npm run test:ai-contract`, `npm run test:journal-identity`, `npm run test:sw`, `npm run test:backup` 및 `tools-verify.ps1`이다. 실행 환경에는 번들 Node·Playwright와 격리된 Edge가 필요하다.

## 다음 구조 이전

1. 여행·일정·기록·지출·사진을 IndexedDB 항목별 원본으로 이전한다. 현재 여행 JSON의 사진 사본과 모든 여행 전체 직렬화는 남아 있다. 원본 백업·변환 대조·중단/용량 실패 복구 없이 사본을 제거하지 않는다.
2. `commitTripCommand`를 나머지 레거시 변경 함수로 확대한다. 현재 localStorage 원문 비교는 일반적인 오래된 탭 저장을 막지만 여러 프로세스의 읽기·쓰기를 원자적으로 잠그는 트랜잭션은 아니다. 항목별 revision과 IDB 트랜잭션으로 최종 이전한다.
3. 화면/모달 이동·작성 중 초안·복귀 위치를 하나의 navigation controller로 묶고 긴 `index.html`을 기능별 controller와 디자인 컴포넌트로 나눈다.
4. 동행 서버의 실제 두 계정·두 기기 권한, 계정 복구·초대 취소·탈퇴·장기 오프라인 충돌을 검증한다. 개인 기록 비공개 경계와 명시적인 공동 계획 확인·전송을 유지한다.

공개 앱은 개인 계획을 기본 자료로 배포하지 않으며 가상 예제를 선택할 때만 추가한다. 배포 파일은 공개 자산 allowlist로 생성한다. 개발 보고서·테스트·첨부·복구 자료는 웹 루트에 올리지 않는다.
