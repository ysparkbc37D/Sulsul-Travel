# JSON 백업·불러오기 개선 — v1.9.2

2026-10-08 사용자가 휴대폰 설정의 JSON 백업·복원 실패를 보고했다. 합성 자료와 Chromium 모바일 에뮬레이션의 실제 탭·파일 선택·다운로드로 조사했다. 단순 정상 파일은 기존 코드에서도 저장·복원되었으므로 모든 휴대폰 버튼이 고장났다고 단정하지 않았다. 그러나 앱이 내보낸 기존 장소 설명의 기본 HTML 서식과 `x < y` 문장은 공유용 검사를 통과하지 못해 같은 앱에서 복원되지 않았다. 구 필드 정규화도 검증보다 늦었다. 손상 문서에서는 공동 계획 보호가 원문 JSON을 파싱하다 복원을 차단했다. 기존 함수 직접 호출 회귀는 실제 설정 버튼과 이런 내용 조합을 검증하지 못했다.

기존 내보내기는 제한 없는 긴 data URL이었지만 읽기는 20MB까지만 허용했다. 실패나 파일 준비 상태도 없었다. [download 속성은 실제 다운로드 발생을 보증하지 않는다](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download). 파일은 Blob으로 만들고, 완료를 단정하지 않고 저장 요청 뒤 다운로드 목록 확인을 안내한다. [파일 공유는 사용자 클릭 활성화가 필요하므로](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share) 비동기 파일 준비와 공유 버튼 클릭을 분리한다. 지원하지 않는 공유 API가 정상 파일 저장을 막지 않는다.

## 사용 흐름

설정의 JSON 백업은 파일을 준비하고 여행·글·사진·지출 수와 크기를 표시한다. 사용자는 파일 저장 또는 지원하는 휴대폰 저장·공유 버튼을 누른다. JSON 복원은 실제 파일 선택 버튼에서 읽고 미리보기를 표시한다. 적용 버튼과 교체 확인을 거치기 전에는 현재 자료를 바꾸지 않는다. 오류는 해당 화면에 남고, 읽기 실패·거절·저장 실패 후 같은 파일을 다시 선택하거나 준비된 검토에서 재시도한다. 창 닫기도 전역 350ms 가드에 묶지 않고 즉시 검토를 취소한다.

전체 백업은 `format: sulsul-backup`, `schemaVersion: 1`, 앱 버전·내보낸 시각·여행 목록을 포함한다. API 키와 계정 설정은 내보내지 않는다. 기존 `{version,trips}` 파일과 BOM을 지원하고, name/timeline 등의 별칭을 정규화한 뒤 검사한다. 원문·기본 서식·평문 비교는 보존한다. 실행 가능한 HTML/속성과 잘못된 식별자·통화·사진 주소는 거절한다. 주요 시간표·체크리스트 등의 텍스트 출력도 escape한다. 사본 링크의 별도 공유 검사는 유지한다. 생성과 읽기 한도는 모두 50MB이며, 큰 파일이라고 기기의 localStorage 용량 제한까지 해결된다는 뜻은 아니다.

## 기록 보존

백업은 현재 여행 복사본에 해당 여행의 최신 IndexedDB 보조 일기를 합친다. 사진 사본이 빠진 경우 같은 여행 소유의 보관 Blob을 파일 안의 data URL로 복구하며, 확인할 수 없는 원본을 조용히 제외하지 않는다. 복원은 저장 성공 이후에만 State를 채택하고 보조 기록·사진을 정리한다. 기존 및 보조 revision보다 높은 로컬 revision을 부여해 정리 실패 뒤에도 오래된 일기가 새 복원을 덮지 못하게 한다.

손상 저장소는 정확한 기존 문자열을 복구 보관본에 먼저 보존하고 사용자 확인 후 `approvedRecoveryRaw`로 저장 경계를 통과한다. JSON 배열이라도 잘못된 여행 객체가 있으면 같은 보존 절차를 거친다. 다른 문자열이나 기본 쓰기는 거절한다. 정상 문서에서는 이 옵션이 보기 전용 계획 보호를 우회하지 않는다. 검토 이후 여행 문서·State가 바뀌었으면 다시 파일을 고르게 한다. 저장 실패 전에 기존 문서나 보조 데이터를 지우지 않는다. 저장 완료 뒤 화면 갱신이 실패한 경우에는 '기존 자료 유지'라고 잘못 안내하지 않는다.

여러 날짜의 보조 일기를 읽을 때는 합치기 전 본문의 revision을 기준으로 검사한다. 앞서 처리한 다른 날짜의 높은 revision 때문에 유효한 글이 빠지지 않으며 같은 날짜는 가장 높은 revision을 유지한다. 보조 글을 먼저 합친 다음 누락된 보관 사진을 채워 글과 사진을 함께 내보낸다. 재접속 시의 보조 일기 복구에도 같은 날짜별 기준을 적용한다.

## 검증 범위

실제 개인 파일과 브라우저 프로필을 사용하지 않는다. 단위/계약 검사는 복구 승인 경계, 구 백업·원문 왕복·실행 자료 거절·크기 한도를 포함한다. Edge의 Chromium 엔진과 Pixel 7 모바일 에뮬레이션에서 실제 Blob 다운로드·파일 선택·미리보기·적용 확인, 취소·저장 실패 재시도, 손상 원문 복구, 보조 일기 정리 실패 뒤 새로고침, 보관 사진 포함을 확인한다. 320/360/390/430px 화면을 측정한다. WebKit 실행 파일이 없어 실제 iOS 엔진과 사용자의 물리 휴대폰 파일 앱은 검증하지 못했다. 휴대폰 저장·공유는 사용자 클릭에서의 API 호출·취소·다운로드 대안을 검사하며 외부 저장 대상에 자료를 보내지 않는다.

이번 변경은 설정의 로컬 JSON 백업·복원이다. GitHub Gist 및 실시간 공동 서버를 사용자의 실제 계정으로 검증한 것은 아니다. 현재 공개 배포는 계속 명시한 앱 자산만 제공하며 백업 파일과 개발 문서는 배포하지 않는다.

최종 로컬 검증은 단위·계약 125개, 백업·복원 브라우저 20개 및 저장 신뢰성·공동 계획 검토·모바일 화면·예제 선택·가계부·이야기 출력 회귀검사를 통과했다. 버전 동기화와 360px 레이아웃을 포함한 배포 게이트도 통과했다.
