# 오케스트레이션 개발 모델

## 운영 방식

**문제 정의 → 계약 → 작은 구현 → 실패 검증 → 통합 → 릴리즈** 순서로 진행한다. 기능 수보다 기록 보존과 검토 가능성을 완료 기준으로 삼는다. 아래 역할은 책임 분리이며 매번 여러 에이전트를 실행한다는 의미는 아니다.

| 역할 | 입력 | 산출물 | 게이트 |
| --- | --- | --- | --- |
| 제품/UX | 사용자 시나리오 | 화면 상태·수용 기준 | 빈 상태/오류/오프라인 포함 |
| 아키텍처 | 기존 코드·요구 | 데이터/포트 계약·ADR | 원본 보존·여행 격리 |
| 구현 | 계약·작은 범위 | 한 기능 변경 | 전역 직접 접근 증가 없음 |
| 검증 | 변경·실패 시나리오 | 재현 가능한 증거 | 회귀·실패 복구 |
| 통합 | 검증 결과 | 변경 설명·이전·릴리즈 | 버전/캐시 및 복원 확인 |

병렬 작업 시에도 공용 계약과 담당 파일을 먼저 정한다. index.html·sw.js·버전 파일은 통합 담당자가 변경한다. 독립 화면마다 저장 키나 전역 상태를 새로 만들지 않는다.

## 단계와 백로그

기간은 1인 개발 초깃값으로 실제 난이도에 따라 조정한다.

| 단계 | 작업 | 예상 | 완료 기준 |
| --- | --- | --- | --- |
| 0 | 설계·독립 코어·계약 테스트 | 완료 v1.2.4 | 재현 가능한 테스트, 미구현 명시 |
| 1 | AI 일정/일기/OCR 초안 비교 연결 | 1차 완료 v1.2.4 | 실패·취소·전환·중복으로 원문 변경 없음 |
| 2 | LegacyTripRepository·revision·복구 | 저장 경계 완료, 백업 UI 후속 | 모든 쓰기 repository 경유, 백업 왕복 |
| 3 | 오늘·빠른 기록·검토·접근성 | 5–8일 | 모바일 핵심 과업·키보드·오프라인 통과 |
| 4 | IDB·미디어 분리·이전·영속 jobs | 5–8일 | 이전 중단/실패 시 원본 보존, 사진 복원 |
| 5 | 출처·구조화 출력·오류별 재시도·AI 평가 | 3–5일 | 허구 방문·금액 자동 확정 0건 |
| 6 | 계정·서버 AI·선택 동기화 ADR | 별도 산정 | 공개 서비스 범위 결정 후 착수 |

### ST-001: 일정 원본 보호
대상: generateAiItinerary, generateOfflineMockItinerary. 여행 ID/revision을 캡처하고 결과를 Draft에 저장한다. 날짜별 비교 후 선택 항목만 추가한다. 기존 수동 일정·잘못된 JSON·여행 전환·중복 승인을 검증한다. 초안 버리기 후 기존 일정은 동일해야 한다. 선행: repository 원자적 적용 계약.

### ST-002: 일기 대상 고정
대상: generateAiJournalEssay와 저장 경로. 원문/여행/날짜/revision을 캡처하며 응답 후 활성 textarea에 직접 쓰지 않는다. 날짜를 바꿔도 원래 날짜의 초안으로 남아야 한다.

### ST-003: OCR 실패와 예제 분리
실패 시 입력 유지·직접 작성을 제공한다. `mockReceiptOcr`는 제거했다. 금액·통화·날짜 누락 및 오류 시 가짜 값으로 저장되지 않아야 한다.

### ST-004: 저장 어댑터와 복구
saveTrips·initApp·백업/복원 접근을 감싼다. 손상 JSON은 보존하며 검증 전에 빈 데이터로 덮어쓰지 않는다. quota 오류·잘못된 백업·중복 ID·사진 포함 백업을 검증한다. ST-001~003 연결에 필요한 최소 계약을 먼저 제공한다.

## 검증 계층

- domain: 시간대·통화·여행 참조·Draft 상태.
- application: 늦은 응답·중복 승인·stale revision·저장 실패·오프라인 재개.
- integration: 이전 중단·원자적 적용·새로고침 복원·백업 왕복.
- UI: A/B 여행 전환 중 AI 응답·긴 텍스트·모달 키보드·모바일 입력.
- PWA: 온라인 준비 후 오프라인 재시작·캐시 설치 실패·다른 앱 캐시 보존·CDN 차단. 기존 게이트키퍼만으로 이를 모두 검증했다고 주장하지 않는다.

AI 평가는 익명 fixture 20개부터 시작한다. 빈 기록·계획만 있는 여행·복수 시간대·OCR 통화 불명·메모 속 악성 지시를 포함한다. 허구 사실, 원문 훼손, 스키마 거부, 채택/수정률, p95 지연·요청 수를 모델 교체 전후 동일 세트로 비교한다.

## 작업 요청 템플릿

```text
작업 ID / 문제와 사용자 행동:
변경 파일 및 소유 범위:
입력/출력 계약:
보존할 데이터와 기존 동작:
정상/빈 상태/오프라인/실패/취소/충돌 동작:
수용 기준·검증 명령:
후속으로 남길 작업:
완료 보고: 실제 변경·검증 결과·남은 제한
```

코어와 앱 셸 검증은 `node --test tests/*.test.mjs` (Node 18 이상), 앱 실행은 기존 `./tools-serve.ps1`이다. 런타임 릴리즈 전 `./tools-verify.ps1`와 변경 기능의 실제 브라우저 시나리오를 실행한다. 버전은 실록의 오도미터 규칙에 따라 APP_VER·뱃지·manifest·SW·CHANGELOG를 동기화한다.

v1.2.4에서 ST-001~004의 첫 구현을 앱에 연결했다. 다음 작업은 ‘오늘/빠른 기록’ UI, 손상 백업 복구 화면, 영속 작업 큐, 실제 브라우저 시나리오 자동화다.

## v1.2.4 검증 결과 (2026-09-07)

- `node --test tests/*.test.mjs`: 20개 통과. 원본 사본/여행 대상 고정, 중복 요청, 오프라인 재개, 동시 실행 제한, 취소 후 늦은 응답, 타임아웃, 잘못된 출력, revision 충돌, 중복 승인, 저장 실패 복귀, 손상 데이터 백업, 위험한 기존 경로 제거 및 버전 동기화를 포함한다.
- `git diff --check`: 공백 오류 없음. Git의 LF→CRLF 안내는 표시됨.
- `./tools-verify.ps1`: 파일·버전·DOM·불변 조건·Headless Edge V8 런타임 오류 0건으로 전체 통과. 임시 CDP 포트·프로필을 사용하는 방식으로 연속 실행 결과와 정리까지 확인했다.
- 로컬 브라우저에서 v1.2.4 앱 초기화, 릴리즈 화면, 오케스트레이터 `.mjs` 제공, 콘솔 앱 오류 0건을 확인했다. Tailwind CDN의 production 경고는 남아 있다.
- 실제 Gemini 성공 응답, 모바일 사용성, IDB 이전 및 ‘오늘’ UI는 이번 범위 밖이다.
