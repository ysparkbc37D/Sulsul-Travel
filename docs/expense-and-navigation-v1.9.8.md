# v1.9.8 지출 사진 저장과 모바일 뒤로가기

2026-11-03 · 기준 v1.9.7(`809212a`). 사용자 개인 여행이나 사진을 검사용으로 읽거나 배포하지 않았다.

## 재현한 문제

- 지출 사진은 800px로 줄여도 모든 여행과 함께 `st_trips_v2`의 data URL에 누적됐다. 격리 Edge에서 복잡한 800×600 JPEG 20장인 합성 문서 약 567만 문자가 실제 `QuotaExceededError`를 일으켰다. 개별 거래의 8장 제한은 전체 저장 한도를 막지 못했다.
- 결제 미리보기와 저장은 사진을 포함한 전체 문서를 반복 복사했다. 사진 16장인 합성 저장에서 약 2,279만 문자가 직렬화됐다. 저장 뒤에는 숨은 시간표·전체 작업 화면·평생 통계까지 다시 그렸다. 데스크톱 계측은 휴대폰 지연 시간의 보증이 아니다.
- 사진 처리 오류와 저장 버튼이 긴 입력 화면 아래에 있었고, 처리 진행률·저장 중 중복 실행 방어가 부족했다. 저장 뒤 렌더 오류도 저장 자체의 실패처럼 보일 수 있었다.
- 일반 모달과 내 여행 목록에는 문서 이탈을 막는 뒤로가기 경계가 없었다. 일정 상세·일정 기록·순간 기록의 분산된 history 처리가 일부 화면에만 적용됐다.

## 적용한 저장 경계

지출 사진은 IndexedDB의 `sulsul-travel-expense-photos-v1/archives`에 고유 ID로 먼저 보관한다. 거래 전체의 완료를 확인한 보관본만 `expensePhotoArchive` 참조를 붙이고, JSON에 직렬화할 때 사진 본문을 분리한다. 메모리의 `photos[]`는 실제 사진을 유지하므로 기존 사진 보기·지갑 계산·출력 경로가 바뀌지 않는다.

새 페이지는 여행 화면 초기화 전에 참조를 읽고 원본을 복원한다. 참조가 누락되거나 IndexedDB가 제한되면 기존 JSON fallback을 사용하거나 입력을 보존하고 실패를 알린다. 읽지 못한 참조는 삭제하지 않으며, 누락 사진을 정상적인 전체 백업이라고 내보내지 않는다. 사진 저장만 성공하고 JSON 저장이 실패한 경우 기존 거래·잔액은 채택하지 않는다. 고유 보관본을 덮어쓰거나 이전 보관본을 자동 정리하지 않는다.

전체 JSON 백업과 금융 포함 사본은 실제 사진을 포함하고 기기 전용 참조를 제거한다. 전체 백업 복원도 지출 사진 보관을 준비한 뒤 기존 원문·revision 충돌 경계에서 채택한다. API 키·인증 정보는 추가로 수집하지 않는다.

저장소 정규화가 독립 복사본을 만든다는 계약을 유지하면서 불필요한 전체 복사를 줄이고, command 후에는 변경한 여행만 다시 정규화한다. 로컬 원문 충돌 검사·보기 전용 공동 계획 보호·저장 성공 뒤 메모리 채택은 유지한다.

## 지출 화면

- 헤더·본문·저장 영역을 분리하여 입력 내용만 스크롤한다. 저장/취소와 처리·오류 안내는 하단에 계속 보인다.
- 사진을 순차 비동기 처리하고 진행률·시간 초과·지원하지 않는 파일을 알린다. 일부 파일이 실패해도 준비된 사진은 유지한다.
- 저장 중임을 먼저 표시하고 중복 저장·여행 변경·입력 세션 변경·저장 중 입력 변경을 검사한다.
- 저장 뒤 지출·지갑 화면을 갱신한다. 숨은 전체 화면과 평생 통계는 지출 저장에서 다시 만들지 않는다. 렌더 오류가 나도 이미 저장된 거래를 실패라고 표시하지 않는다.
- 대표사진 한 장을 목록의 고정 썸네일로 표시하고 전체 사진은 열어서 확인한다. 실패 시에는 입력과 사진을 유지하고 초안 파일로 보관할 수 있다.

## 뒤로가기

사진 확대 → 가장 나중에 연 편집창 → 큰 계획 상세 → 내 여행 목록 순서로 복귀한다. 미저장 편집은 기존 확인을 거치며 저장 중에는 닫지 않는다. 내 여행 목록에서 다시 뒤로가면 **앱을 종료할까요?** 창을 표시한다. 모달 밖에서 쓰던 하루 회고·사진 초안도 확인해 유실 가능성을 알리고, 취소하면 초안을 유지한다. 계속 사용은 현재 문서에 남고, 앱 종료를 선택하면 뒤로가기 가드를 해제하고 이전 문서 복귀 또는 지원하는 창 닫기를 시도한다.

브라우저는 웹 앱이 모든 탭이나 OS 창을 강제로 닫는 것을 허용하지 않는다. 닫기가 지원되지 않으면 이를 안내하고 다음 시스템 뒤로가기·탭 닫기를 허용한다. 또한 Chromium의 사용자 상호작용 전 history 건너뛰기 정책 때문에 설치 직후 아무 터치 없이 누른 첫 OS 뒤로가기를 모든 기기에서 보장하지 않는다. 앱 안에서 터치한 뒤 경계를 재설정하며, 자동화의 `page.goBack()` 결과를 실제 Android/PWA 종료 성공으로 과장하지 않는다. [브라우저 창 닫기 계약](https://developer.mozilla.org/en-US/docs/Web/API/Window/close), [History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API).

## 검증 범위

합성 사진·여행만 사용하는 격리 Chromium에서 고해상도 사진·부분 실패·저장 중 표시·실패 재시도, 실제 IndexedDB 보관과 새 페이지 복원, JSON 저장 한도 경계, 완전한 백업·다른 사진 저장소에서 복원, 두 탭 충돌과 누락 참조 보존을 검사한다. 뒤로가기의 사진·모달·미저장 편집·상세·허브 복귀, 종료 취소·확인과 새로고침 후 가드 수를 검사한다.

최종 단위 검사 197건, 뒤로가기 10건, 실제 IndexedDB 6건을 통과했다. 4개 여행·45일 일정의 사진 16장에 실제 파일 입력으로 4장을 추가하고 저장 버튼을 눌렀다. 기존 전체 JSON 5,695,042자는 실제 용량 초과가 났고, 개선 경로는 JSON 123,375자와 별도 보관 참조 4개로 사진 20장을 유지했다. 재실행의 실제 사진·대표 인덱스와 사진 저장소가 없는 별도 환경에서 읽는 백업까지 확인했다. 320~430px 및 높이 560/844px에서 저장 버튼의 실제 클릭 영역을 확인했다.

누락 사진 부팅 검사에서는 초기화 뒤 `renderCompanionPlan → saveTrips({bump:false})`가 자동 저장하는 추가 경로를 발견했다. 공통 자동 저장 방어 후 원문 동일·부팅 쓰기 0회·여행과 일기 표시·누락 참조 유지·불완전 백업 거절을 실제 새 페이지에서 확인했다.

브라우저 저장소 자체를 사용자가 삭제하거나 기기가 공간을 모두 소진하면 사진 보관도 보장할 수 없다. 중요한 여행은 전체 백업 파일을 따로 보관한다. 실제 iOS와 물리 Android 기기 검증은 별도다.
