# v1.8.9 기능 개선과 검증

2026-10-07. [v1.8.8 모바일 검토 보고서](ux-review-v1.8.8-2026-10-07.md)의 작업 묶음 A~E를 기존 정적 PWA에 연결했다. 프레임워크나 사용자 저장 데이터를 전면 교체하지 않았다.

## 구현 연결

| 보고서 묶음 | 연결한 기능과 구조 |
| --- | --- |
| A 입력 계약 | TripAdapter가 시드/구버전/공유/AI 결과의 title·cat·ISO 날짜·안정 ID를 보충한다. 전체 도시명과 원본 별칭을 보존한다. 여행 단계와 현지 날짜/시각을 허브·작업 화면·오늘·지출에서 함께 사용한다. |
| B 모바일 탐색 | 다음 일정의 길찾기·기록·완료, 비/이동 지연/휴식 이유의 날짜별 튜닝, 완료 일정 접기, 72px 날짜 선택, 상단 도구 메뉴, 여행별 탭·날짜·보기·스크롤 복원을 연결했다. 모던·딥블랙·라이트그레이 보조 글색을 수정했다. |
| C 순간과 사진 | momentEntries는 같은 날 여러 글/사진과 선택 일정 연결·공개 범위 표시를 저장한다. journals/activityRecords는 보존한다. AI 승인·원문·충돌·저장 실패 초안·삭제 확인·뒤로가기를 연결했다. 비율 유지 사진/썸네일과 IndexedDB Blob은 JSON fallback과 함께 동작한다. |
| D 이야기 출력 | TravelStory는 날짜별 예정/완료/건너뜀·실제 기록·순간·하루 회고와 출처 manifest를 구성한다. 기존 PDF 표지/정산과 원문/승인문·사진 옵션, Markdown/텍스트 내보내기에 같은 모델을 연결했다. 식비/교통 분류를 통일했다. |
| E 공동 계획 | 선택 Supabase REST·설치 SQL·보기/편집 초대·만료/취소·멤버·이력·revision 충돌·오프라인 대기 변경을 구현했다. 사용자 비교/승인과 로컬 저장 성공 뒤 연결한다. 보기 권한 저장 경계는 개인 기록을 허용하고 공동 계획 변경을 막는다. 기본 서버 설정은 비어 있다. |

일정 길찾기는 저장된 좌표 또는 전체 도시/장소 이름을 Google Maps URL로 전달한다. 앱 내부의 실제 교통 소요 시간을 측정했다고 표시하지 않으며 지도에서 경로와 시간을 확인하도록 안내한다. 전체 앱 셸의 레거시 함수와 ID는 남아 있으므로 새 기능은 모듈 계약을 통해 점진적으로 옮긴다.

## 데이터 보존

- 시드·구버전 입력은 원본 필드/사진/완료·고정·기록 참조를 유지하며 필요한 화면 필드를 보충한다. 이미 사라진 도시명은 남아 있는 일별 도시 데이터로만 복구하며 추측하지 않는다.
- 순간 기록은 기존 하루 회고나 일정 글을 덮어쓰지 않는다. AI 승인문과 원문을 따로 보존하고 출력에서 선택한다. 알려지지 않은 발생/작성 시각을 수정 시각이나 예정 시각으로 채우지 않는다.
- 새 사진 보관본은 최대 긴 변 1600px, 썸네일은 448px이다. 작은 사진을 확대하거나 보관본을 강제로 3:4로 늘리지 않는다. 기존에 잘린 사진의 원래 영역은 복구할 수 없다.
- JSON의 photos와 IndexedDB Blob을 함께 보관한다. 따라서 localStorage 한도는 남는다. Blob 참조가 없거나 내용이 다르면 JSON 보관본을 사용한다. 순간·하루 사진 저장 실패는 초안을 유지해 재시도/파일 보관할 수 있다.
- 여행 삭제·전체 백업 복원은 문서 저장 성공 뒤 미참조 사진 Blob을 정리한다. 다른 여행 사본이 사용하는 사진은 유지하며, 보조 저장소 정리 실패는 삭제·복원 성공과 구분해 안내한다.
- 공동 서버에는 계획만 보낸다. 개인 글·사진·지출·인증 정보는 제외한다. 원격 계획 적용은 안정적인 spot ID로 개인 기록 연결을 유지하고, 서버에서 사라진 일정의 기록도 기록 피드에 남긴다.

모바일 대표 글의 측정 최소 대비는 모던 4.966:1, 딥블랙 5.798:1, 라이트그레이 4.960:1이었다. 검사한 대표 화면의 결과이며 앱 전체 WCAG 인증을 뜻하지 않는다. 실제 휴대폰의 카메라·키보드·메신저 링크 인식은 별도 확인이 필요하다.

협업 코드의 독립 검토에서 확인한 프로젝트 전환 중 토큰 전송 위험, 다른 탭 outbox 항목 손실, 서버 게시 후 로컬 연결 실패 시 중복 게시 문제를 수정하고 mock 회귀로 검사했다. **실제 Supabase SQL 실행·RLS·두 기기 공동 편집은 수행하지 않았다.** [서버 설치 안내](collaboration-setup.md)의 운영 검증 후 활성화해야 한다.

## 남은 확장 과제

공동 계획은 명시 확인/전송과 비교/승인 방식이며 자동 실시간 병합은 제공하지 않는다. 기본 서버가 없어 배포만으로 동행 초대가 활성화되지 않는다. 공개 서버 설정·Auth/CAPTCHA·권한 검증과 계정 복구/문서 삭제 정책이 필요하다. 서버에 개인 기록을 공유하는 기능도 아직 연결하지 않았다. 순간의 공개 범위는 현재 기록 표시이며 사본 파일에서 개인 글 포함을 선택하면 나만 보기 기록도 전달됨을 명시한다.

장기적으로 미디어 참조만 저장하는 전체 데이터 이전, 이메일/OAuth 계정 연결과 여러 기기 복구, 전체 여행의 기록 탐색, 지도/실시간 이동 API와 출처 표시, 샘플을 개인 여행으로 복사하는 온보딩을 별도 확장해야 한다. 4개 하단 메뉴 전환은 사용자 적응을 확인할 후속 작업이며 이번 버전은 기존 5개 연결을 보존했다.
