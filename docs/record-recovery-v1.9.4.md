# v1.9.4 기록 저장과 AI 다듬기 복구

2026-10-12 사용자 화면의 `SulsulTravel.TripAdapter.getJournalEntry is not a function`을 실제 구버전으로 재현하고 수정했다. 사용자 기록이나 API 키를 테스트에 사용하지 않았다.

## 원인과 실제 저장 상태

실제 `ac317b0`(v1.9.2)의 서비스워커와 공개 자산을 격리 프로필에 설치하고, 워커 업데이트가 지연된 상태에서 v1.9.3 HTML을 열었다. 구 워커의 `cache.match(...,{ignoreSearch:true})` 때문에 새 버전 쿼리에도 이전 TripAdapter가 반환됐다. 새 화면이 호출하는 `getJournalEntry`는 이전 모듈에 없었다.

일정 기록 저장은 기기 문서에 성공했지만 뒤이은 `renderJournalTab()` 예외까지 같은 catch가 처리해 false를 반환했다. AI 다듬기는 원문 선행 저장이 false라서 요청 전에 중단됐다. 따라서 재현된 오류는 ‘글이 저장됐는데 실패로 안내되고 AI가 시작되지 않는 문제’다. 사용자의 실제 휴대폰 저장 상태를 직접 확인한 것은 아니다.

## 수정 경계

- HTML에 공개 로컬 JS/CSS 33개의 SRI를 넣는다. 불일치하면 초기 여행 로드·정규화·저장 전에 `SulsulShell`이 업데이트 복구 화면을 연다. 저장된 여행, 사진, 키는 삭제하지 않는다.
- 실제 배포 디렉터리의 파일 바이트로 해시를 다시 계산해 Windows/Git 개행 변환 차이를 없앤다. 자산 수정 후 개발용 HTML 해시도 갱신한다.
- 새 워커가 준비된 최초 복구는 안전하게 재시작한다. 앱 사용 중 워커 교체는 안내만 표시한다. 열린 창·미저장 회고·대기 사진·AI 작업이 있으면 업데이트 버튼의 재시작을 막는다.
- 같은 워커의 공개 캐시 파일이 손상된 경우 명시 재시도는 실패한 앱 JS/CSS 항목만 다시 받는다. 개인 localStorage/IndexedDB는 정리하지 않는다.
- 일정·순간 저장과 삭제는 기기 저장 성공과 화면 갱신 오류를 구분한다. 일부 화면 실패가 AI 원문 저장 성공을 뒤집지 않는다.
- 하루·일정·순간 AI 승인에서 최초 원문과 사진을 유지한다. 하루 회고의 미저장 수정과 충돌하면 승인하지 않는다. 저장 실패 초안은 그대로 남는다.
- 사진 삭제는 최초 여행·일정 ID·사진 목록과 revision을 검증하고, 저장 실패 시 원본과 확인창을 유지한다. 다른 여행의 사진을 삭제하지 않는다.
- 여행 기간이 줄면 유효한 하루 회고 날짜를 선택한다. 재계획으로 일정 날짜·제목·시각이 바뀌어도 이미 남긴 기록과 출력은 당시 문맥을 보존한다.

## 검증과 제한

`service-worker-upgrade.browser.cjs`는 실제 v1.9.2 캐시에서 공개 빌드로 업그레이드한다. 자산 불일치 시 기기 문서가 바뀌지 않고, 새 워커 후 하루·일정·순간 원문을 유지하며 저장·AI 검토·승인·명시 재시작까지 확인한다. `record-persistence.browser.cjs`는 같은 렌더 오류를 강제로 주입해 실제 기기 저장과 AI 결과를 확인한다.

일기 날짜/사진 삭제/AI 충돌 회귀, 일정·순간 기록, 백업·복원, 여행기 PDF·Markdown·텍스트 출력도 합성 자료로 검사한다. 서비스워커 캐시 검사는 실제 Chromium에서 실행한다. 실제 휴대폰 iOS 엔진과 사용자의 Gemini 계정 호출은 확인하지 않았다. AI 응답·한도·인증 오류는 별도일 수 있다.

릴리스 확인 결과: 단위 검사 162개, 실제 구버전 업그레이드/손상 캐시 36개, 하루 회고 경계 14개, AI 계약 28개, 서비스워커 17개, 백업 20개와 일정/순간/저장 오류/출력 브라우저 회귀를 통과했다. 모바일 320·360·390·430px와 768·1280px를 확인했으며 `tools-verify.ps1` 릴리스 게이트도 통과했다.

사진이 포함된 전체 여행의 localStorage 용량 한계와 완전한 여러 탭 트랜잭션은 남아 있다. 사진/원본 저장소 이전과 화면 분리 등 구조 과제는 [v1.9.3 보강 범위](architecture-hardening-v1.9.3.md)에 유지한다. v1.9.3의 새 프로필 검사만으로 구 워커 사용자의 업데이트까지 검증했다고 볼 수 없었던 점을 실록 98호에 기록했다.
