# 여행 다이어리 UI/UX 명세

상태: 다음 화면 개편 명세. 앱 화면 구현은 후속이다.

## 정보 구조와 대표 화면

허브는 진행 중 → 예정 → 지난 여행 순이다. 평생 통계는 접을 수 있는 요약, 카드 대표 행동은 여행 열기로 통일한다. 여행 내부는 **오늘 · 일정 · 기록 · 지출** 네 탭이다. 준비물은 일정의 준비 영역, 공유·백업·키 설정은 더보기로 이동한다. 전환 기간 기존 DOM ID는 보존한다.

```text
┌──────────────────────────────┐
│ ‹ 내 여행    운남 여행    ⋯   │
│ Day 3 · 다리   기기에 저장됨  │
├──────────────────────────────┤
│ 오늘 남긴 순간 3개           │
│ [사진] 호숫가에서 마신 커피   │
│ 09:20  메모 한 줄             │
│                              │
│ 다음 일정 · 14:00 고성 산책  │
│ [일정 보기]                  │
│                              │
│ 오늘의 여행기 초안이 있어요  │
│ 기록 3개를 바탕으로 작성     │
│ [초안 살펴보기]              │
│                              │
│       [＋ 순간 기록]         │
├──────────────────────────────┤
│ 오늘    일정    기록    지출  │
└──────────────────────────────┘
```

## 핵심 여정

1. 첫 사용: 여행 이름·기간·목적지 → 여행 생성 → 첫 기록. API 키와 설치 안내는 흐름을 막지 않는다. 예제는 별도 표시하고 내 여행으로 복사를 제공한다.
2. 수집: 순간 기록 → 사진/메모 → 로컬 저장. 날짜·장소는 수정 가능하며 GPS 권한은 필수가 아니다. 키보드가 저장 버튼을 가리지 않게 한다.
3. 하루 마감: 기록 선택 → 전송 자료 확인 → 생성 → 원문/초안 비교 → 수정/채택. 기초 기록이 없으면 메모를 안내하고 방문 사실을 만들지 않는다.
4. 회고: 날짜별 탐색 → 확정 여행기로 구성 → 사진/표지 선택 → 미리보기 → 내보내기.

## 상태 문구

| 상태 | 문구 | 다음 행동 |
| --- | --- | --- |
| 비어 있음 | 오늘 기억하고 싶은 순간을 남겨보세요 | 순간 기록 |
| 오프라인 | 기록은 기기에 저장돼요. AI 정리는 연결 후 가능해요 | 계속 기록 / 재개 |
| 생성 중 | 선택한 기록 3개를 정리하고 있어요 | 취소 |
| 초안 준비 | 여행기 초안이 준비됐어요 | 비교하고 적용 |
| 충돌 | 초안 생성 후 원문이 바뀌었어요 | 변경 내용 비교 |
| AI 실패 | 초안을 만들지 못했어요. 원래 기록은 보관돼 있어요 | 재시도 / 직접 작성 |
| 저장 실패 | 기기 저장에 실패했어요 | 다시 저장 / 기록 복사 |
| OCR 실패 | 금액을 읽지 못했어요 | 사진 다시 선택 / 직접 입력 |

키 입력됨과 연결 확인됨을 구분한다. 기기에 저장됨·백업됨·동기화됨도 각각 다른 상태다.

## 시각·접근성·반응형

- 앰버·에메랄드 정체성을 유지하고 primary/surface/text/muted/warning/danger/draft 토큰을 라이트·다크별 정의한다. 초안·오류는 색 외에 텍스트/아이콘을 함께 쓴다.
- 내부 목표: 터치 영역 44×44px 이상, 본문 16px, 본문 대비 4.5:1 이상. 실제 측정 전 AAA 달성이라고 주장하지 않는다.
- 360/390/768/1280px, 긴 한국어·장소명·200% 확대를 검사한다. 페이지 가로 넘침을 허용하지 않는다.
- 모바일 단일 열, 넓은 화면은 기록 목록/상세 두 영역. 사진 크기를 예약하여 레이아웃 이동을 줄인다.
- 모달 제목·초기 포커스·포커스 가두기·Escape·포커스 복원, 저장 상태 aria-live, 사진 대체텍스트, 감소된 모션, 하단 safe-area를 제공한다.

## 측정

초기 목표는 아직 검증되지 않은 가설이다. 첫 기록 60초 이내, 재방문 빠른 기록 3번 이내 조작, 오프라인 저장 성공, 기존 기록 유실 0건을 우선 평가한다. 사용자 5명으로 첫 기록·초안 채택·OCR 수정·여행 전환을 관찰한다. 분석 도입 시 동의 기반 성공 여부/소요시간만 수집하고 본문·사진·위치·키는 수집하지 않는다.
